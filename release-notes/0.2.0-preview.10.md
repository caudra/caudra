> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 10.** On its first start, Preview 10 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout), and the upgrade needs exclusive access. This includes other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 10 does not start. It lists the open sessions to close instead, and nothing is changed.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `caudra.db.v28.bak` next to `caudra.db`. Preview 9 and earlier cannot open the upgraded database, and `caudra rollback` restores only the previous binary, not the database.

> [!WARNING]
> **Before you start Preview 10, rename `ui.tool_output_lines.python_execution` to `ui.tool_output_lines.code`.** The `code` tool replaces `mcp` and `python_execution`, with no alias. A `caudra.toml` that still sets the old key fails to load, with an error that names the new one. Permission rules, `agent.disabled_tools` entries, and system prompt profiles that name the `mcp` or `python_execution` tool no longer match anything, so name `code` in them instead. See [Code](https://caudra.ai/docs/code/).

> [!WARNING]
> **If you run a remote Workcell server, update it with Caudra and rename its `python_execution` tool group to `code`.** Workcell's Python tool is now `code` too, so `--tool-group python_execution` and `python_execution` in `WORKCELL_MCP_TOOL_GROUPS` fail at startup. Caudra requires a server that serves `code`, and refuses an older one. See [Remote workspaces](https://caudra.ai/docs/remote-workspaces/).

> [!WARNING]
> **If your workflows call `decide()`, rewrite their questions when you update.** Questions are now a list instead of a map keyed by ID, so each question names itself with `name`. `noul` questions become `predicate` questions, and `criteria` becomes `choices` for a choice and `levels` for a score. Answers come back as `answers`, a list in question order, and `by_name`, keyed by name, and a predicate's probability is now in `probability` rather than `noul`. A workflow that still passes the old shape fails at its first `decide()` call with a catchable error, and so does a run started before the update when you resume it, even at a call it had already answered. See [Typed decisions](https://caudra.ai/docs/workflows/#typed-decisions).


> [!WARNING]
> **If your config, profiles, or remote Workcell use the code-graph tools, update them together with Caudra.** `code_context` and `code_refs` are now `source_code_context` and `source_code_refs`, and `code_map`, `code_impact`, and `code_expand` are gone: use `source_code_context` where you used `code_map` or `code_expand`, and `source_code_refs` with `depth` where you used `code_impact`. The profile tool group `code_graph` is now `source_code`, and `[decisions.features] code_context` is now `source_code_context`. A config or profile that still names an old tool, group, or feature is rejected as unknown. Your sessions, `/tools` usage, decision log, and saved permission rules move to the new names the first time Caudra starts, and sessions that called a removed tool still open and show those calls. A remote Workcell must run the same release as Caudra, or connecting fails with an incompatible tool catalog, and its `--tool-group code_graph` is now `--tool-group source_code`. The SDK's tool kinds are now `SourceCodeContext` and `SourceCodeRefs`. See [Code Intelligence](https://caudra.ai/docs/tools/#code-intelligence).

> [!IMPORTANT]
> **Intel macOS users building with Nix must switch to the native build.** Current nixpkgs no longer supports Intel macOS, so the flake no longer provides `x86_64-darwin` outputs. Native Intel macOS builds and release binaries remain supported.

### Code

- **One `code` tool replaces `mcp` and `python_execution`.** The model runs all of its Python in `code`: computation, MCP server calls, history search, and the decision helpers. It is offered in every session, with or without MCP servers, and its definition never changes, so the prompt cache holds. Variables persist between runs of the same agent, and `reset: true` starts a run empty. A model that still calls `mcp` or `python_execution` gets an unknown-tool error. `/tools`, `caudra tools`, and `/mcp` mark MCP tools `via code`. See [Code](https://caudra.ai/docs/code/).
- **Computation runs where snippets run.** Python now always runs on your machine, also in sessions on a remote Workcell. A run has 30 seconds of computation, where `python_execution` stopped at 5 seconds unless the model asked for more, and the clock stops while a snippet waits for a call. `timeoutSec` is gone. One agent's runs go one at a time, so the model gathers parallel work in one snippet, and a `code` call starts once the model's response is complete. See [Where snippets run](https://caudra.ai/docs/code/#where-snippets-run).
- **Search your past conversations.** `history.search()` finds what you wrote, what the model answered and reasoned, and what its tools did, in this conversation, this project, another project, or every stored session, compacted turns and subagents included. Each hit carries a snippet around the matched words and a reference that `history.read()` opens in full, and `history.sessions()` lists sessions. A full-text index in the session database fills in the background while the TUI is open, and each search catches it up first. Searching this project never asks. Another project or all projects ask first. The prompt shows the call with its arguments and which session or project's history it reads, and offers to always allow that history. See [Search past conversations](https://caudra.ai/docs/code/#search-past-conversations).
- **Reranked history search.** With the experimental decision engine on, set `[decisions.features] history_search = "enforce"` and the engine judges up to 64 keyword matches against the query, drops those below `thresholds.relevance_floor`, and returns the 10 most relevant. Its four requests go out at once, and each waits up to four times `rerank_timeout_ms`, so an engine that answers one request at a time can still judge the whole pool. Otherwise a search returns 20 matches in keyword order. The feature is off by default, and `shadow` logs what it would have kept. See [Ranking](https://caudra.ai/docs/code/#ranking).

### MCP

- **Decisions and reranking in snippets.** With the decision engine on, a `code` snippet can call `decide()` for typed answers about its data, and `rerank()` to keep only the candidates relevant to a query, best first, for up to 256 candidates. A snippet can rank 200 issue titles and return the ten that matter, so the rest never reach the model. The model is told how to write questions and queries that get reliable answers, such as naming the field each question judges and describing every option. Both work with or without MCP servers. Calls need no approval, work in plan mode, show as rows on the card, and appear in the decision log under the feature `code`. See [Decisions and reranking](https://caudra.ai/docs/code/#decisions-and-reranking).
- **Decision answers you can read at a glance.** A `decide()` row on the `code` card shows its verdicts on one line, and always shows each question below it with a bar per option, the likeliest highlighted, and a warning when the winner is uncertain. A `rerank()` row always shows the candidates it kept, best first, under the labels they were given. Click the row's footer to see the JSON the snippet received; selecting any part of the row copies that JSON, in either view. In `/decisions`, Recent draws logged answers the same way, and `j` switches them to JSON.

### Workflows

- **`decide()` takes OpenAI Decisions questions.** A choice option or a score level can carry a description, as a map with `value` or `label` and `description`, and each answer lists the probability of every option or level. Both decision protocols return the same shape. `rerank()` is unchanged.

### Transcript

- **Pictures in the transcript.** `view_image` and `image_generate` cards, Markdown images that point at local files, and prompts with attached images now show the picture as a thumbnail. Terminals that support Kitty graphics get the full-resolution picture, and other terminals get coloured blocks, two by two pixels to a cell, or two by three with `inline_images = "sextants"` in terminals and fonts that draw sextants. Click a picture to open it at full size, then press `o` to open it in your system viewer, `w` to open it in the workbench, or `y` to copy its path. Images attached to a draft show as `[Image #1]` chips you can click, and the workbench shows image files instead of the binary file notice. Markdown images are never fetched from the network. Set `[ui] inline_images` to `"blocks"`, `"sextants"`, `"kitty"`, or `"off"` to choose. See [Images](https://caudra.ai/docs/markdown/#images).

### Questions

- **Add a note to your answers.** On a question the agent asks, `F5` opens a note for anything the options and your answers leave out, even while you type an answer. The note shows on every tab and in the review, and a click edits it. `Enter`, `Esc`, or `F5` again leaves it with the text kept. It reaches the agent with your answers, and with the dismissal when you press `Esc` on the form. `Ctrl+C` still stops the agent, and moves the note to the composer to start your next message. Questions from MCP servers and consent requests have no note. The form's hints now start with `Enter submit`, then `F2 Ask /btw`. See [Keybindings](https://caudra.ai/docs/keybindings/#form).

### Selection

- **Drag to copy in `/btw` and the question form.** Dragging over a `/btw` thread copies the passage when you let go, the way the transcript copies: within one answer as its Markdown, and across questions and answers as sections headed `User`, `Assistant`, `Thinking`, and `Error`, without the footer, the follow-up field, or a line break at every wrapped row, and the passage stays selected while the answer streams and scrolls. `Ctrl+Y`, `Ctrl+C`, and the footer's copy take the selection before the whole answer. In the question form, a drag starts anywhere, including on an option, and copies instead of picking what it ends on. A drag in the answer box selects and copies its text, and `Ctrl+C` copies a selection before it stops the agent. The form's border is no longer copied with the text. See [Commands](https://caudra.ai/docs/commands/) and [Keybindings](https://caudra.ai/docs/keybindings/#form).

### Goals

- **A goal that stops getting anywhere stops its run.** When three turns in a row make no progress, the run ends with the goal still active instead of spending continuations until the limit. A turn makes no progress when the evaluator saw nothing new, when it repeats an earlier turn exactly, or when the agent stops to ask you something. Progress is read from the conversation, so work on a remote system counts once a tool result shows it. Autopilot reviews the stall like a loop cap: a continue buys one more turn, and its review streak still leaves the fourth continue in a row to you. Headless clients get a `stalled` goal event. See [Commands](https://caudra.ai/docs/commands/).
- **A goal waiting on something outside the session waits instead of stalling.** When the evaluator sees the goal waiting on a change that comes by itself, such as a CI run or a deploy, the run ends and the goal is checked again after a minute, then twice as long each time up to 30 minutes, for eight waits, about two hours. Then it stalls as before. A question to you never waits, and a message from you ends the wait. The wait is saved with the session, so a resumed session checks in when it is over. Headless clients get a `waiting` goal event. See [Commands](https://caudra.ai/docs/commands/).
- **Automations hear about a stuck goal.** A `goal_finished` trigger that lists `stalled` in `verdicts` fires when a run stops on a goal that made no progress or used its continuations. The goal stays active, so a reply can still finish it. See [Automations](https://caudra.ai/docs/automations/).

### Image generation

- **ChatGPT subscription image generation uses a supported model.** Image requests now run through GPT-6.1 Sol instead of GPT-5.5, which OpenAI retired from Codex with ChatGPT sign-in on October 14. This fixes the unsupported-model error without changing your configured image model or switching to API billing.

### Source code tools

- **Two source code tools instead of five, under new names.** `source_code_context` (formerly `code_context`) finds the code a task touches, and `source_code_refs` lists who calls a symbol. `source_code_refs` takes `depth` to show what a change could reach, with a count per hop and how many of the reached symbols are tests, which is what `code_impact` did. Both tools are always in the request for every model, so a small model no longer has to search for them first. The system prompt names them with one line each and points the model at `source_code_refs` instead of grep for callers.
- **Call sites in `source_code_refs`.** Each caller row lists the lines that make the call, up to 16 per row with a count of the rest, so one call finds every place a change must touch. Callees come in the order the body calls them. A call linked by its name alone, because the receiver's type was never seen, is marked `~name` and no longer moves the ranking.
- **Standard library calls stay out of the graph.** In Rust, a call such as `.clone()`, `Vec::new()`, `Arc::new()`, or `std::mem::take()` no longer links to a symbol of the same name in your tree. A common method name links only when the calling file names the type that defines it, and `source_code_refs` says how many same-name calls it left unlinked. A bare call reaches only free functions, and a method call reaches only methods.
- **`source_code_context` lifts only the names you write.** A name in the task lifts its symbol only when written as code, such as `build_csr`, `` `parse` ``, `a::b`, or `run()`. An ordinary word such as "renew" no longer pulls in every `new`, and a symbol that matches only through its file's path, such as a constructor in a file the task names, ranks below one whose own name matches.

### Tools

- **`/tools` counts calls made inside `batch`.** Each call a batch makes now has its own row with its own outcome, time, and tokens, and the `batch` row keeps the wall time of the whole batch. The token total is unchanged.

### Fixes

- **A session with a stored tool card this build cannot read opens again.** Such a card, like an `mcp` card from Preview 9, is skipped, and its call shows the text the model received. Before, the whole session failed to open.
- **Lua job cleanup survives cancellation and deadlines.** Releasing an abandoned `jobwait` during garbage collection no longer aborts the process, including when the plugin host shuts down.
- **Shell output keeps unrelated subcommands intact.** Updated bundled filters no longer match commands merely because their names start with a filtered subcommand.
- **PHP indexing handles clone arguments and partial application.** File indexes and code graphs no longer report parse errors for these expressions.
- **Go type aliases appear in file indexes and code graphs.** Declarations such as `type Alias = Target` are now included as type definitions.
- **SVG source icons enforce pixel-buffer limits across nested effects.** Allocation checks now include linked masks and clips, retained filter results, and drop-shadow scratch buffers. Over-budget icons are skipped.
- **HTML conversion preserves code layout and lazy-loaded images.** Code blocks retain blank lines and image placeholders resolve correctly. Equally scored article candidates now follow document order.

### Builds

- **Nix evaluation works without building the worker source first.** The pinned Python worker source is fetched and verified during evaluation, without import from derivation.
- **Workcell container builds include all attribution sources.** The Debian 13.7 image fetches both locked dependency graphs before generating its offline license bundle.
