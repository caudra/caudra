- Images and PDFs are stored once as files beside the session database, which shrinks it, and resumed sessions keep their PDFs.
- A task whose transcript is too large to save no longer stops every background task, and a result lost that way is delivered after a restart.
- The agent can write reminders and follow-ups for its own session, and one-shot automations can disarm themselves after acting.
- Emil Kowalski's design-engineering skills ship as an opt-in pack beside pstack and mattpocock.
- In a project with few memory notes, the agent is reminded to save one after it learns something worth keeping.
- The agent asks for an API token on a private card, and shell commands receive it as a variable without the value entering the chat.

> [!IMPORTANT]
> Close other Caudra sessions before starting Preview 17. Its first start moves the images saved in sessions into the media store, which can take a few minutes on a large database.
>
> Updating from Preview 16 saves a copy first at `backups/caudra.db.v43.bak` in the state directory. Older builds cannot open the upgraded database, and `caudra rollback` restores only the previous binary.

### Changes

- **Secrets for shell commands.** When a command needs a token, the agent asks for it on a private card instead of in chat. The session's shell commands receive it as an environment variable, such as `$CLOUDFLARE_API_TOKEN`, and the value stays out of the transcript, logs, and requests to the model. When a command prints it, the output shows `${CLOUDFLARE_API_TOKEN}` instead. A secret lasts 24 hours in its session, or you can remember it for all sessions. `/secrets` opens the new Secrets section of `/env`, where you replace, move, and delete them. Secrets reach shell commands on this machine only. An agent that can run commands can still read a secret and send it elsewhere, so review commands that use one as you would any other. See [Secrets](https://caudra.ai/docs/secrets/).

- **The agent starts saving notes in new projects.** While a project has few memory notes, the main session gets a one-time reminder to save one after a failed command passes, after a long search ends in an edit, or when the context nears compaction. With the new `memory_nudge` decision feature, a message in which you correct the agent or state a rule triggers one as well. Reminders get rarer as notes accumulate, come at most 3 times a day per project, and stop once the agent saves notes without them. `[agent] memory_nudges = false` turns them off. A project with no notes also explains notes in its memory view, and the background learner runs after 3 typed messages instead of 10. See [Memory](https://caudra.ai/docs/memory/#reminders-to-save-notes).

- **Git-aware automations.** Experimental automations can use `git_compare(base)` to compare a checkout with a local branch without a model turn. Caudra's contributor checkout includes `sync-main`, which asks for a merge at a safe point when local `main` moves and skips when the worktree is current. See [Automations](https://caudra.ai/docs/automations/#compare-local-git-branches).

- **Agent-managed automations.** With experimental automations on, the agent can write ad-hoc reminders and follow-ups visible only to its session. These session scripts need no digest trust and disappear when the session is deleted. Arming asks for permission unless a rule, YOLO, or autopilot approves. Session disarm and delete need no prompt by default, though your deny or ask rules still win. Project and user disarm and delete still require permission. Approving an arm also trusts an untrusted project script's exact reviewed digest, with its triggers, args and capabilities shown before approval. Reading and validating automations need no prompt. A one-shot script can call `done(reason)` to disarm itself when its firing completes, without dropping its queued message. See [Automations](https://caudra.ai/docs/automations/).

- **emil skills.** `[plugins.skill] emil = true` adds [Emil Kowalski's skills](https://github.com/emilkowalski/skills), translated for Caudra, as the `emil` skill and a `/emil:<name>` command for each of the 16. They build, review, audit and remove animations, make a web app feel native on a phone, stress-test a UI with worst-case data, prototype variants, and cover Sonner and modern Swift. Audits ask which findings to plan through `question` and write the plans into the session plan. Visual checks use screenshot tooling your project already has, and findings Caudra could not see are labelled as inferred from the code. Switching the pack applies at once in the terminal UI. See [emil](https://caudra.ai/docs/skills/#emil).

- **The old Lua tools are gone.** Caudra no longer ships the Lua versions of its built-in tools, which stopped loading when the tools became native. Plugins can still `require` the `caudra.*` modules. A plugin that required one of those tools' own files, such as `edit_helpers` or `lang.rust`, now needs its own copy. See [Plugins](https://caudra.ai/docs/plugins/).

- **Images and PDFs are stored once.** Pasted images, images that tools and tasks return, and fetched PDFs are saved as files under `media/` in the state directory, and sessions keep only a reference to each. The same picture in several sessions, forks, or task transcripts takes space once, and the upgrade moves images already saved into the store. Resumed sessions now keep their fetched PDFs. If a file goes missing, the model is told the image is unavailable instead of receiving it. The storage sweep and `caudra storage prune` remove files that no session, archive, or backup refers to after seven days. Backups keep the files they refer to, so restoring one needs the `media/` directory beside it. `/storage` and `caudra storage stats` show the store's size, and `caudra storage check` reports missing or damaged files. See [Sessions](https://caudra.ai/docs/sessions/).

- **`/btw` keeps its thread.** Closing `/btw` now keeps the thread, one per chat, until you press `Ctrl+L`, click `Clear`, or the session changes. `F2`, `/btw`, and `/catchup` reopen it with its earlier answers. If the conversation moved on, the next question reads it as it stands, with the thread's last 10 questions and answers quoted. Threads stay in memory and are never saved. On the Plan complete form, `F2` or `Ask /btw` asks a side question without leaving the form, and every control on that form, the question form, and the `/btw` footer shows a tooltip on hover. See [Commands](https://caudra.ai/docs/commands/).

### Fixes

- **Automation state reaches the agent.** With experimental automations on, messages from a completed `done()` firing tell the agent that the script disarmed itself. A `# Automations` reminder lists armed scripts and explains changes made through user controls or by the runtime, without repeating the agent's own tool actions.

- **Large task transcripts.** A task whose transcript grew past what the session database can hold, such as one that generated many images, stopped all background tasks with `string or blob too big` until Caudra restarted. Its result is now saved and delivered without the transcript, and continuing the task picks up from the session's own copy of its history. After you update, restart Caudra once to deliver a result already lost to this error.

- **A task's footer shows the model it switched to.** After you switched a running task to another model or thinking level, its footer and its card in the main chat went back to the old model as soon as the task did anything else, and a reopened session showed the old model too. The task's result also told the main agent it ran on the old model. All three now name the new model. They also update when a task moves to another account's model because the first account ran out.

- **One resume row.** Resuming a turn that a shutdown cut off showed three rows: the shutdown marker and two that both said "Resumed after interruption". It now shows the marker and a single row naming what resumed, such as `Resumed after interruption: main turn`, and both stay when you reopen the session. See [Sessions](https://caudra.ai/docs/sessions/).
