- Sign in to one provider with several subscriptions and API keys, and let Caudra switch between them without breaking the prompt cache.
- Config edits keep your comments.
- Opt-in cache warming keeps the Anthropic prompt cache alive through long tool runs.
- Editors and desktop apps get more of Caudra over ACP: several sessions, session management, sign-in, steering, and background subagents.
- Image generation, the host description, workflows, and automations move into the `code` tool as modules with on-demand help, and `tool_search` is gone.
- Snippets can sleep and read the clock, and `timeoutSec` bounds a run.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 11.** On its first start, Preview 11 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout) to record which account served each turn and what cache warming cost and saved, and the upgrade needs exclusive access. This includes other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 11 does not start. It lists the open sessions to close instead, and nothing is changed.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `caudra.db.v30.bak` next to `caudra.db`. It also moves each saved provider login to `auth/accounts/<provider>/default.json`. Preview 10 and earlier cannot open the upgraded database or read the moved logins, and `caudra rollback` restores only the previous binary.

> [!WARNING]
> **Before you start Preview 11, remove the settings that deferred tools.** `image_generate`, `execution_environment`, `workflow`, and `automation` are now [modules of the `code` tool](https://caudra.ai/docs/code/#tools-reached-from-code), and `tool_search` is gone with the deferral it served. A config or profile that still uses any of the following fails to load, with an error that names the fix:
>
> 1. Delete `defer_builtin_tools` from `[agent]` in `caudra.toml`.
> 2. Delete `tool_search` from `[decisions.features]`.
> 3. Replace `lazy` in a [system prompt profile](https://caudra.ai/docs/system-prompts/#choose-tool-availability)'s `tools` block with `eager` or `disabled`. An MCP tool that was `lazy` stays callable as `eager`.
> 4. Remove `code` from `agent.disabled_tools` and from profile overrides that disable it. `code` now hosts the modules and cannot be turned off, so turn off a module's tool group instead: `images` for `image`, `execution` for `host`, and `delegation` for `workflow` and `automation`.
>
> Permission rules, `agent.disabled_tools` entries, and profile groups that name the four tools keep working, because a module call runs the tool under its own name. A model that calls one of them directly, or inside `batch`, gets an error naming the module call. In snippets, `decide()`, `rerank()`, `search()`, `servers()`, `resources()`, and `read_resource()` are now `decisions.decide()`, `decisions.rerank()`, `mcp.search()`, `mcp.servers()`, `mcp.resources()`, and `mcp.read_resource()`, and the old names raise `NameError` naming the new call. Sessions that called the old tools still open and show those calls.

### Code

- **Modules with on-demand help**: A `code` snippet now reaches everything beyond the interpreter through modules: `history`, `mcp`, `decisions`, `image`, `host`, `workflow`, and `automation`. The `code` description carries one line per module, and `help()` lists the modules and whether this session can reach each, while `help("image")`, `help("workflow.start")`, or `help("github")` loads the full reference with examples. The first `history.search`, `history.read`, `image.generate`, or `workflow.start` in a conversation raises with its reference instead of running, unless `help` already showed it, so the call made again has the arguments right. The description no longer changes with what the session connects, so the prompt cache holds. See [Modules](https://caudra.ai/docs/code/#modules).
- **Tools as module calls**: `await image.generate(prompt, out)`, `await host.environment()`, `await workflow.start(...)`, and `await automation.list()` run the tools they replace, with the same permission rules, plan mode checks, change records, `/tools` usage, and cards. The prompt shows the call as the snippet made it, and the call's row on the `code` card opens to the tool's own card, image thumbnail included. Snippets receive dicts: an image's saved `path`, the host's facts and commands, and the workflow and automation runtime's records. Every model sees the same short request, since nothing is deferred any more. See [Tools reached from `code`](https://caudra.ai/docs/code/#tools-reached-from-code).
- **Sleep and clocks**: `time.sleep()` and `await asyncio.sleep()` now wait for real, and `time.time()`, `time.monotonic()`, and `datetime.now()` read the host clock in UTC. The card shows `waiting 10s` while a snippet waits, and `Esc` stops it. Waiting does not count toward the 30 seconds of computation. See [The Python subset](https://caudra.ai/docs/code/#the-python-subset).
- **`timeoutSec` is back as a deadline**: A `code` run stops after `timeoutSec` seconds, 120 by default and up to 3600, counted on the wall clock across computation, waits, and calls. A run that times out keeps the variables from before it and the rows of the calls it made, so a snippet can poll a workflow with `asyncio.sleep` under a raised `timeoutSec`. See [Run time](https://caudra.ai/docs/code/#run-time).
- **JavaScript habits repaired**: A snippet that starts an assignment with `const`, `let`, or `var`, or passes a host call one JavaScript object such as `image.generate({prompt: ...})`, now runs as the Python it meant, and the model reads that snippets are Python. Every repair is found in the parsed snippet and kept only when the result parses. The system prompt, the `code` description, and its parameter now show the calling convention up front, which smaller models need. See [Results and errors](https://caudra.ai/docs/mcp/#results-and-errors).

### Accounts

- **Several accounts per provider**: Each `caudra auth login` adds an account, such as a second Claude subscription or an API key, and `--name` names it. Signing in again as an account you already have refreshes it. `caudra auth status` lists the accounts of every provider with the quota they have left, `caudra auth use <provider> <name|auto>` chooses one, and `caudra auth rename` and `caudra auth logout <provider> [name] [--all]` manage them. See [Accounts](https://caudra.ai/docs/accounts/).
- **Automatic switching**: With two or more accounts, Auto keeps each conversation on its account and moves it to another before the account runs out. It moves only where the prompt cache is cold anyway, unless the account is nearly spent or refused. `ordered` tries the accounts in priority order, and `paced` uses the quota that resets soonest. `[<provider>.switching]` and `[[<provider>.accounts]]` in `providers.toml` set the thresholds, the order, and which API keys may take over from spent subscriptions. See [How Auto switches](https://caudra.ai/docs/accounts/#how-auto-switches).
- **Accounts in the TUI**: `/accounts` or `Ctrl+X i` lists, pins, adds, renames, orders, and removes accounts, with fresh quota readings for each 5-hour and weekly window. The status bar shows the account a conversation uses with its quota, each switch adds a transcript row with its cause and cache cost, and a spent account asks whether to switch or wait. `/usage` lists every account of the provider and splits lifetime spend by account.
- **Across providers**: With `[switching] providers = ["anthropic", "openai"]` in `providers.toml`, Auto moves a conversation to another provider's subscription once every subscription of its own runs out, on the first of your favorite models there, and back once the first provider has quota again. Each move adds a transcript row with its cause and cache cost. `/accounts` now lists every provider's accounts, and `o` and `Alt+↑↓` set the order. See [Across providers](https://caudra.ai/docs/accounts/#across-providers).
- **One run on another account**: `--account <provider>:<name|auto>` and `CAUDRA_ACCOUNT` choose an account for one run without saving the choice.
- **xAI sign-in in the TUI**: `/login` offers the xAI subscription sign-in beside an API key, and `caudra auth login xai --method api-key` stores a key.

### Cache warming

- **Opt-in cache warming**: `cache_warming = "running"` under `[agent]` in the global `caudra.toml` sends the last request again with `max_tokens: 0` shortly before its Anthropic prompt cache expires, while a run waits on a long tool, subagent, question, or permission prompt. `"idle"` also warms for up to 30 minutes after a run ends. It is off by default, covers the Anthropic API only, and warms only when one avoided cache write is worth more than the warms. See [Cache warming](https://caudra.ai/docs/token-economy/#cache-warming).
- **What warming would save**: `/usage` has a `Cache warming` block for the session and for all time, with what warms cost and saved. While warming is off, it shows what warming would have done as `estimated if enabled`, so you can decide before turning it on.

### ACP

- **Several sessions**: One `caudra acp` process now keeps every session an editor opens, instead of closing the previous one on each new or loaded session. Each session runs its own tools, so sessions in different projects or sandboxes run side by side. A loaded session resumes on the model it recorded while policy allows it, and loading a session that is already open replays it again. See [ACP](https://caudra.ai/docs/acp/).
- **Session management**: Editors can now list, resume, close, delete, and fork Caudra sessions. The list shows the same local sessions as the TUI's session picker, and a fork keeps the conversation and permission mode but starts without the source's conversation approvals. The session title reaches the editor when the model names the session and when a named session opens. See [Sessions](https://caudra.ai/docs/acp/#sessions).
- **Sign-in**: Editors now get a `caudra-login` auth method that runs `caudra auth login`, as a terminal method where the editor supports one and through Zed's `terminal-auth` metadata otherwise. A session whose provider has no credentials is refused with `auth_required` when it opens, and `authenticate` checks again after you sign in. `caudra acp` also starts on a machine with no signed-in provider, so the editor can offer the sign-in. See [Authentication](https://caudra.ai/docs/acp/#authentication).
- **Pickers and model catalog**: Editors now get pickers for reasoning effort, mode, and permission mode beside the model, and a fast mode toggle where the model and the editor support it. Models are grouped by provider. Every change, including a reroute to another provider's model, reaches the editor as a `config_option_update`, and the effort level and fast mode are saved with the session. Editors can also list models before opening a session, from `initialize` or `_caudra/models/list`, and hear about new ones through `_caudra/models/changed`. See [Config options](https://caudra.ai/docs/acp/#config-options).
- **Slash commands and compaction**: Editors now list `/compact`, your skills, and MCP prompts as slash commands, and running one does what it does in the TUI. Editors that support them also see compaction progress and a notice for each retried provider request. See [Slash commands](https://caudra.ai/docs/acp/#slash-commands).
- **Cancellation and steering**: Cancelling a prompt withdraws open permission prompts and questions and answers `cancelled` exactly once, even when the cancel arrives before the turn starts or the agent takes more than 5 seconds to stop. A prompt sent right after a cancel runs once the cancelled turn ends, so editors such as Orca that steer by cancelling and prompting again work. A prompt sent with `_meta.caudra.delivery: "steer"` joins the running turn instead. `$/cancel_request` cancels a running prompt or a request still queued behind a starting session. See [Prompts, cancellation, and steering](https://caudra.ai/docs/acp/#prompts-cancellation-and-steering).
- **Turn details**: Every update and answer names its prompt id, and the answer adds the turn's duration and usage. A turn Caudra starts on its own, such as one reporting a finished background task, answers no prompt, so the prompt sent while it runs gets its own turn. Message and thought chunks carry message ids that stay the same when a session is loaded again. Tool calls name their tool, shell calls report stdout, stderr, and exit code as structured output, and calls a turn left running end as cancelled. Usage and spend, side calls included, reach the editor after every response and on load. Refusals end the prompt as `refusal`, missing or rejected credentials fail with `auth_required`, and failures carry their text instead of a bare "Internal error". See [Turn updates](https://caudra.ai/docs/acp/#turn-updates).
- **Subagents and background tasks**: Subagents and shell commands can now run in the background over ACP, as in the TUI. Editors that support ACP subagent sessions get one per subagent, which they can cancel on its own. Editors that opt in with `_meta["caudra/childWork"]` get `_caudra/*` notifications for subagent progress and background commands, plus requests to cancel a subagent or kill a command. Every other editor sees each subagent's tool calls in the parent session, labelled with the subagent. Cancelling a turn or closing a session stops this work. See [Subagents and background tasks](https://caudra.ai/docs/acp/#subagents-and-background-tasks).
- **Questions as permission requests**: An editor without form elicitation that sets `_meta["caudra/questionsViaPermission"]` gets the `question` tool's questions as permission requests. URL-mode MCP elicitations now send `elicitation/complete` when they finish. See [Permissions and questions](https://caudra.ai/docs/acp/#permissions-and-questions).
- **Answers every request**: A second prompt to a busy session is refused instead of leaving the first one unanswered forever, and a request for a session that is not open gets a resource-not-found error. A slow session start no longer holds up cancels and permission answers for other sessions. A line on stdin that is not JSON or is over 64 MiB is skipped instead of breaking the connection, and a failed runtime shutdown now refuses only its own session.
- **Stopping finished work is no error**: `_caudra/subagent/cancel` and `_caudra/task/kill` answer `{"outcome": "stopped"}` when they stop something, and `{"outcome": "not_running"}` with the final `status` when the subagent or command already ended. Only one the session never ran gets `invalid_params`. `session/cancel` for the child session of a finished subagent does nothing. See [Subagents and background tasks](https://caudra.ai/docs/acp/#subagents-and-background-tasks).
- **History previews**: `session/list` entries carry `_meta.caudra.firstPrompt` and `lastPrompt`, the first and last prompt you typed, cut to 280 characters. `caudra storage sessions --json` gives each session `first_prompt`, `last_prompt`, and `model`. See [Sessions](https://caudra.ai/docs/acp/#sessions).

### Changes

- **Image inspection**: The image viewer and workbench image tabs now support zoom and pan, with fit and actual-size views. Clicking outside the picture closes the viewer, including its blank margins, without activating the transcript underneath.
- **Image sizing**: The image graphics probe now checks PNG support and asks for cell pixel dimensions when the terminal can report them. Resizing or changing the font no longer reuses a raster made for a different pixel size. Automatic mode retains block rendering inside Herdr while its placeholder path remains unverified.
- **More Python in `code`**: Monty 1.2 adds CSV parsing, hashing, TOML parsing, bisection, `os.path`, match statements, and dataclass field defaults. Python still has no direct access to the host filesystem or network.
- **Orca resumes Caudra**: The status Caudra reports in an Orca terminal now carries the session id as `sessionId` once the session is saved, so Orca can reopen it with `caudra --resume <id>`. While subagents run, it also lists them, and Orca shows each as a child row under the agent. Off Windows, clicking a row switches Caudra to that subagent's chat when Orca supports it, and clicking the agent's own row switches back to the main chat. See [Orca](https://caudra.ai/docs/notifications/#orca).
- **Docs from any modal**: A `?` on the top border of a modal such as `/accounts`, `/usage`, or `/permissions` opens the section of the manual about it, and `F1` does the same. The docs open above the modal, so `Esc` returns to it. A link from `/changelog` into the docs also opens above the release notes now instead of closing them. See [Docs](https://caudra.ai/docs/commands/#docs).
- **Clickable title hints**: The key hints on the top border of `/usage` (reload, lifetime or session, more or less) and `/tools` (the next view) now answer a click as their key does, and highlight under the pointer.
- **Keys in one variable are accounts**: A provider key variable holding several keys separated by commas becomes the accounts `env-1`, `env-2`, and so on, which Auto chooses between like any others, instead of rotating through them on every error.
- **A saved key wins over the variable**: A key `caudra auth login` saved is now tried before the provider's key variable.
- **Short rate limits wait**: A rate limit shorter than 30 seconds now waits on the same account, which keeps its prompt cache, instead of moving to the next key.
- **Logout keeps `providers.toml`**: `caudra auth logout` now deletes only the credential. An account entry in `providers.toml` stays and shows as signed out, and the next login without `--name` fills it.
- **Hidden key prompts**: `caudra auth login` no longer shows an API key as you type it.
- **Recognised calls open whole**: A [Home Assistant](https://caudra.ai/docs/mcp/#home-assistant) or [Executor](https://caudra.ai/docs/mcp/#executor) call inside a `code` or `batch` card shows its whole card, as the same call does on its own. A click folds its row and the next opens it again. The compact view and `ui.always_collapsed` still fold them.
- **Resources read as their type**: An MCP resource whose type is not markdown now shows its text as the server wrote it instead of rendering it as markdown, and the Home Assistant Assist context snapshot draws as the same table of entities as `GetLiveContext`.
- **Lookups fold like a file read**: `source_code_context`, `source_code_refs`, and `memory` reads now rest as one row in every `/view`, and a click on the row opens the whole answer instead of three rows of it. They join the default `ui.always_collapsed` list, and the new `memory_read` entry covers a `memory` call's view, zoom, search, and read without its writes. If you set your own `always_collapsed` list, add `"source_code_context"`, `"source_code_refs"`, and `"memory_read"` to it to get this.
- **Memory writes show the whole note**: A `memory` write draws the whole note it stored, the way a `file_write` draws the whole file, instead of its first seven lines.
- **Writes fold in expanded**: A click on the title of a write, an edit, a patch, or a memory write now folds it to its header in the expanded `/view` too, and the next click opens it whole.
- **Purposes sorted by spend**: The session's Per purpose table in `/usage` now lists the purpose that cost the most first, as the all-time view does, instead of the one that used the most tokens.
- **Refusals end the turn**: A provider refusal or content filter now ends the turn as refused. An empty refusal no longer reads as a stalled reply that Caudra nudges the model to retry.

### Fixes

- **Cancelling stops the running command**: Cancelling a turn while a `shell` command runs, with `Esc` in the TUI or a cancel from an ACP editor such as Orca's Stop button, now stops the command and every process it started. Before, the command kept running to the end, and `caudra acp` could wait for it before exiting.
- **Config edits keep your comments**: Saving a provider or decision endpoint, toggling an MCP server, or saving sandbox records now changes only the keys that changed. Comments on the other keys, quoting, inline tables, and table order stay as you wrote them, and a new table goes after the existing ones of its kind.
