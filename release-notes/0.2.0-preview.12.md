- Caudra learns from your conversations in the background and keeps what it learned in your instruction files and project memory.
- pstack's engineering skills come built in, off until you turn them on.
- Config files upgrade themselves to a new format, with a backup first and a note on every line they change.
- `/settings` edits `caudra.toml`, `websearch` follows the backends you choose, and `webfetch` reaches the local servers you list and reads Reddit again.
- More lookups rest as one row that says what they found, and a `code` card folds a printed dict or list to a tree.
- Cards say how many tokens a result adds, with estimates that learn each model's tokenizer from what its provider billed.
- Shell cards show an ETA from a small model that learns from your own past commands, with no decision endpoint.
- Decisions show on the tool call's card, apply as soon as you save them, and content screening can withhold a flagged result.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 12.** On its first start, Preview 12 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout). The upgrade needs exclusive access, including from other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 12 does not start and changes nothing. It lists the sessions to close instead, with each one's process ID and title.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `backups/caudra.db.v32.bak` in the state directory. Preview 11 and earlier cannot open the upgraded database, and `caudra rollback` restores only the previous binary.

> [!WARNING]
> **Before you start Preview 12, close older Caudra sessions so it can upgrade your config files.** `caudra.toml` moves to format version 3, and `mcp.toml` and `permissions.toml` to version 2. Preview 12 rewrites the global files when it starts, after it saves a copy of each, but only while no other Caudra process is running. Otherwise it reads them upgraded in memory and leaves them unchanged on disk, and saving to them from inside Caudra, such as with `/env` or `/mcp`, fails until Caudra starts with no other session open.
>
> Preview 11 and earlier cannot read an upgraded file. To go back, copy the file's backup from `backups/config/global/` in the state directory over it. Files in a project's `.caudra/` are never rewritten on their own. If you commit them, run `caudra config migrate --project` once everyone who shares them runs Preview 12. See [Config file versions](https://caudra.ai/docs/configuration/#config-file-versions).

### Models

- **MAI-Code-1.1-Flash on GitHub Copilot.** `copilot/mai-code-1.1-flash` and `copilot-enterprise/mai-code-1.1-flash` now have their price and size class before Copilot's model list arrives: $0.20 per million input tokens and $1.20 per million output tokens. Caudra counts it among the Fast models. See [Copilot](https://caudra.ai/docs/providers/#copilot).
- **GPT-6 Astra and Claude Fable 5.1 on GitHub Copilot.** Both cost $10 per million input tokens and $50 per million output tokens on Copilot. Caudra used to bill Fable 5.1's cache reads at Fable 5's $1 instead of $0.25, so a Fable 5.1 session's cost in `/usage` comes out lower from now on.

### Changes

- **Continual learning**: Caudra now learns from how you work with it, in the background. After at least 10 messages you typed and 2 hours since the last run, once the session has been idle for a minute, a read-only learner on the new **Learn** model job reads the project's recent conversations and checks each finding against the project's history. Caudra writes what will still hold to a managed block in the project's `AGENTS.md` (shared conventions), `AGENTS.local.md` (your machine's setup, which Caudra keeps in `.gitignore`), `~/.config/caudra/AGENTS.md` (your own preferences), or project memory notes. It never edits text outside its block. The status bar says when a run changed something. `/learn` lists the runs with what each changed, opens a run's transcript with `t`, runs one now with `n`, reverts a change with `u`, and pauses the project with `p`. It is on by default. Turn it off with `[agent] continual_learning = false`, or narrow where it writes with `learning_targets`. Its spend shows under `learning` in `/usage`. See [Continual learning](https://caudra.ai/docs/learning/).
- **More lookups fold like a file read**: `history`, `tool_output`, `skill`, `host.environment`, `list_sessions`, `read_topic`, and `automation` calls, and the `plan`, `workflow`, and `task_control` calls that only read, now rest as one row that says what they found, such as how many hits a search kept or a run's state. A click opens the whole answer. Calls that change something keep their cards open. The new `plan_read`, `workflow_read`, and `task_control_read` entries of the default `ui.always_collapsed` list cover the reading calls. If you set your own `always_collapsed` list, add the entries you want from the [default](https://caudra.ai/docs/configuration/#ui).
- **Printed dicts and lists fold to a tree**: When a `code` snippet prints or returns a dict or a list, the card shows it as a folded tree, such as `▸ {…} 7 keys`, and a click opens or folds any part of it. The raw view of an MCP call's card draws its JSON as the same tree. When the tree only repeats one call's answer, such as `print(await host.environment())`, that call's card shows open instead. The model still reads the output as text. See [In the transcript](https://caudra.ai/docs/code/#in-the-transcript).
- **Clearer card titles**: A skill's card reads `Skill loaded <name>`. `task_control`, `workflow`, and `automation` cards have their own titles with the action as a verb, such as `◷ Jobs checked shell-66` or `⑂ Workflow started review`, in place of the tool's name and raw action. Titles set the names and paths they show in italics.
- **Cards say what a result costs the context**: A card whose result the model reads now estimates its tokens beside what it found, such as `209 lines · ~2.1k tokens` on a file read. Caudra counts tokens locally with OpenAI's tokenizer, and now learns from what each provider billed how far that count is off for each model, and keeps it across sessions. Card counts, the `/context` breakdown, the tool ledger in `/usage`, and automatic compaction all use what it learned. See [Watching it work](https://caudra.ai/docs/token-economy/#watching-it-work).
- **`code` cards keep a clock**: A `code` card's header counts up while the snippet runs and then shows how long it took, such as `· 2.4s`, as a `shell` card does. A run that slept no longer shows a stray separator, and its `batch` row keeps what it found. See [In the transcript](https://caudra.ai/docs/code/#in-the-transcript).
- **Time and usage move into the `⋮` menu**: Tool card headers no longer end in the time and the request's usage. The first line of a message's `⋮` menu shows them, with the date when the message is not from today, for every prompt, reply, reasoning block, and tool call, in restored sessions too. A running turn's messages and a subagent's transcript have the menu as well. See [Message actions](https://caudra.ai/docs/sessions/#message-actions).
- **Choose your web search backends**: `websearch` used Exa's hosted search no matter what you set. It now follows `WORKCELL_WEBSEARCH_BACKEND` and `SEARXNG_URL`, and the new `[websearch]` table in the global `caudra.toml`. List several backends in `backends`, such as `["searxng", "exa-mcp"]`. In the default `fallback` mode, the next one answers when one fails. `single` uses only the first, and `all` lets the model pick one per call. Edits apply at once in every open session of the terminal UI. With nothing set, `websearch` uses Exa's hosted search as before. See [Web search](https://caudra.ai/docs/web-search/).
- **Edit `caudra.toml` from `/settings`**: `/settings` has a Web search tab that shows whether each backend is ready and lets you set up, reorder, and switch them, and tabs for the top-level keys, `[ui]`, `[agent]`, the builtin skills, `[provider]`, `[storage]`, `[worktrees]`, `[autopilot]`, and `[automations]`. Switches, value chips, and list editors change a key, and `/` filters every tab. The pane under the list explains the selected key, its default, and when an edit applies, and `?` opens its section of the configuration reference. It writes the global `caudra.toml` and keeps your comments. A key your project's `caudra.toml` also sets is marked, since the project value wins. See [Configuration](https://caudra.ai/docs/configuration/).
- **Decision settings apply as soon as you save them**: On the Features tab of `/decisions`, click a feature's mode or press `Space` or `Enter` to move to its next, such as `off`, `shadow`, then `enforce`. Caudra saves it under `[decisions.features]` in the global `caudra.toml`, keeping your comments. An edit to `[decisions]` or `ui.show_decisions` in `caudra.toml`, to the active decision endpoint's table in `providers.toml`, or to `decisions/permission.json` now applies at once in every open session, without `/reload`. A project `caudra.toml` that turns a feature off still wins. See [the decision engine](https://caudra.ai/docs/permissions/#decision-engine-advice) and [Hot reload](https://caudra.ai/docs/configuration/#hot-reload).
- **Decisions about a call ride on its card**: A decision about a tool call, such as a `source_code_context` rerank or Auto screening, no longer draws its own row under the card. The card's header shows a chip, such as `◆ reranking…` and then `◆ reranked`, and opening the card shows the decision and its scores. Chips that warn, such as `◆ asked you`, use the warning colour. Decisions about a turn, such as a memory recall, keep their rows. See [Decision rows in the transcript](https://caudra.ai/docs/permissions/#decision-rows-in-the-transcript).
- **Rerankers judge a wider pool in one request**: With a [decision endpoint](https://caudra.ai/docs/providers/#decision-endpoints), a rerank now sends up to 64 candidates in one request instead of 16 at a time. `memory_search`, `history_search`, and `source_code_context` judge up to 64, and in `enforce`, `source_code_context` keeps only the rows at or above `thresholds.relevance_floor` unless none clears it. A request waits one `rerank_timeout_ms` for every 16 candidates, and `rerank_timeout_ms` now defaults to 3000 instead of 2000. A workflow run paused in the middle of a `rerank()` on an older release fails when it resumes. See [Reranking](https://caudra.ai/docs/configuration/#reranking).
- **Decision requests wait up to 10 seconds by default**: `[decisions] timeout_ms` now defaults to 10000 instead of 800, so a busy or local engine no longer runs out of time and leaves a feature without an answer. A slow engine can now hold a screened tool call, or the start of a turn for memory recall, for up to that long. Set `timeout_ms` lower to fall back sooner. See [`decisions`](https://caudra.ai/docs/configuration/#decisions).
- **Content screening can withhold a result**: The new `content_screening = "enforce"` keeps a flagged `webfetch`, `websearch`, `code`, or MCP result from the model, which reads a notice in its place asking it to tell you. Caudra deletes the result's saved copy, so `tool_output` cannot read it back. The card keeps the result for you, marked `Decision engine: withheld from the model`. Enforce fails closed: a result is also withheld when the engine fails or times out, or when part of it could not be screened. The feature still defaults to `off`. See [the decision engine](https://caudra.ai/docs/permissions/#decision-engine-advice).
- **Shell ETAs from your own runs**: A shell card's ETA now comes from a small model that runs on your machine and learns from the commands you run, in place of the `shell_duration` decision feature. It needs no decision endpoint and sends nothing anywhere. A command like one you ran before shows how long that took, such as `ETA ~40s`, and others show `ETA seconds` or `ETA minutes` when the model is confident. It only labels the card and changes no timeout. On its first start, Preview 12 trains it from the newest 20,000 shell calls your saved sessions hold, keeping only hashes of each command's words, and the first shell command after Caudra starts waits while it trains. It is on by default. Turn it off with `[agent] shell_eta = false`. The `shell_duration` feature and its thresholds are gone, and the config upgrade comments out those keys. See [`agent`](https://caudra.ai/docs/configuration/#agent).
- **pstack built in**: Lauren Tan's [pstack](https://github.com/cursor/plugins/tree/main/pstack) skills for Cursor now ship with Caudra under their MIT license, with the `deslop`, `control-cli`, and `control-ui` skills from Cursor's team kit. Turn them on with `[plugins.skill] pstack = true`. The agent then sees one `pstack` skill whose index lists every skill and whose pages load by address, such as `pstack/poteto-mode`, translated to name Caudra's tools, paths, and commands. Each skill you run directly gets a `/pstack:<name>` command, pstack's task profiles appear, and its scripts become `pstack` calls in `code`, ported to Rust so they need no Bun, Node, or Bash. If `gh` keeps its login in `GH_TOKEN` or a keyring, forward those variables with `/env`. Benny's Slack triage and watch-pr's drive mode ship as [automations](https://caudra.ai/docs/automations/): with `experimental.automations` on, they are listed in `/automations` under the new `bundled` scope, ready to arm. See [pstack](https://caudra.ai/docs/skills/#pstack).
- **`webfetch` reaches the servers you list**: `webfetch` refuses private, loopback, and carrier-grade NAT addresses, so it could not read a local dev server or a machine on your tailnet. The new `[web]` table in the global `caudra.toml` lists the ones it may reach in local sessions. `allow_private_hosts` takes exact `HOST:PORT` entries, such as `"localhost:3000"`, and `allow_private_networks` takes `loopback`, `private`, `cgnat`, `tailscale`, or a CIDR. When `webfetch` refuses a private target, the error names the `HOST:PORT` to list. Remote workspaces and sandboxes keep the public-internet rule. See [`[web]`](https://caudra.ai/docs/configuration/#web).
- **`webfetch` reads Reddit**: Reddit answers page fetches with a script challenge, so `webfetch` could not read any post. It now reads threads, subreddits, user pages, and searches from Reddit's feed or JSON API, and gives the model the post and its comments as Markdown. A rate-limited fetch on any site that sends `Retry-After` now says how many seconds to wait.
- **Config files upgrade themselves**: Every TOML config file now has a format version in its top-level `version` key. When a release changes a format, Caudra upgrades your files and keeps your layout and comments, with a comment above each line it changes, such as `# Upgraded by Caudra 0.2.0-preview.12 on 2026-10-20: renamed ...`. A removed key is commented out rather than deleted. A notice says when a project file is behind. `caudra config migrate` upgrades the global files on demand, `--project` adds the project files, and `--dry-run` shows a diff without writing. See [Config file versions](https://caudra.ai/docs/configuration/#config-file-versions).
- **Old keys are upgraded instead of refused**: Keys from earlier releases that stopped Caudra with an error, or silently stopped matching, now move to their new form when the file is upgraded. For example, `code_context` and `code_refs` become `source_code_context` and `source_code_refs` in `caudra.toml` and `permissions.toml`, `[python_execution]` becomes `[code]`, and `[bash]` becomes `[shell]`, so rules written under those names apply again. Removed keys, such as `agent.defer_builtin_tools` and the top-level `defer_tools` in `mcp.toml`, are commented out. A file that sets both an old key and its new name is left unchanged, with an error that names both. The legacy decision endpoint keys in `[decisions]`, such as `base_url`, still stop Caudra with the error that shows the `providers.toml` table to write.
- **Backups have their own folder**: Copies Caudra saves before it changes a file now go to `backups/` in the state directory, such as the session database before a schema upgrade and each config file before an upgrade. Backups are owner-only and never deleted. Database backups from earlier releases stay beside `caudra.db`. See [Backups](https://caudra.ai/docs/configuration/#backups).

### Fixes

- **Content screening reads the whole result**: It read only a few samples from the start of a result, so an instruction in the middle of a long page was never checked. It now reads the whole result in overlapping chunks.
- **Switching decision endpoints keeps flagged content flagged**: A session whose content screening had flagged web or MCP output lost that flag when you switched the decision endpoint. It now keeps it.
- **Every task card names its model**: Every task card and `batch` row now names the model its subagent runs on, while the task runs, after it finishes, and after a reload.
- **No false "statement of intent" nudge while work runs**: The nudge that a turn ended on a statement of intent now waits until no task, background job, or workflow is running.
- **Claude models on GitHub Copilot cache their prompts**: Claude models through `copilot` and `copilot-enterprise` never marked where the prompt may be cached, so every turn sent the whole conversation as fresh input. They now mark it the way the `anthropic` provider does, so later turns read the conversation from the cache.
- **Copilot Enterprise takes a tenant name**: A GitHub Enterprise hostname without a dot, such as `company`, now means `company.ghe.com`.
- **`/login` says why it failed**: A failed sign-in from the TUI now carries the reason the login gave.
- **Caudra starts when a provider's credentials are gone**: If the model you last used belongs to a provider whose saved login was removed, Caudra now starts and opens `/login` instead of stopping.
- **One token reads `~1 token`**: Card sizes said `~1 tokens`.
- **The selected row in `/decisions` is readable**: In the dark themes, the whole selected row now takes the highlight's colours.
- **Background commands keep their clock**: A `shell` command sent to the background now counts its time while it runs, then shows how long it took and its final state, such as `succeeded`, even after you reopen the session.
- **A stray indent no longer stops a `code` run**: A snippet with a line indented deeper than the one before it no longer fails with `Unexpected indentation`. Caudra lines the line up with its block, and the card lists the fix. See [Results and errors](https://caudra.ai/docs/mcp/#results-and-errors).
