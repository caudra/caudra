- Clicking the update banner, or running `/update`, installs the new release and restarts Caudra on the same sessions.
- A shell command still running after 10 minutes moves to the background, and tasks and shell commands have one way to run there.
- Commands list their arguments as you type, and dashed commands such as `/goal-clear` became subcommands such as `/goal clear`.
- Todo lists fill in while the model writes them.
- `/catchup` summarizes a session you lost track of, and `/btw` works in subagents chats.
- Decision calls count toward your spend in `/usage`, goal spend, and Autopilot's `max_cost`.
- Long sessions stay fast, and long subagent runs no longer block background results.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 14.** On its first start, Preview 14 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout) to keep each background task's transcript beside its record. While another terminal, editor session over ACP, or `caudra storage` command still has the database open, Preview 14 lists those sessions and does not start. It also moves the global `caudra.toml` to format version 5.
>
> Both upgrades save a copy first: the database as `backups/caudra.db.v38.bak` and `caudra.toml` under `backups/config/global/`, both in the state directory. Preview 13 and earlier cannot open the upgraded database or read the upgraded `caudra.toml`, and `caudra rollback` restores only the previous binary. See [Config file versions](https://caudra.ai/docs/configuration/#config-file-versions).

### Changes

- **Long shell commands move to the background**: A shell call waited for its command however long it ran. It now waits up to 10 minutes, then the command becomes a background job without a restart, and the agent gets the output so far. The result arrives when the command exits or reaches its `timeoutSec` deadline. Change the wait with `agent.shell_foreground_limit_secs`. `agent.shell_async_threshold_secs` is retired, and Caudra comments it out with the reason. The SDK `init` message reports `shell_execution.foreground_limit_secs` in place of `async_threshold_secs`. See [Execution policies](https://caudra.ai/docs/sessions/#execution-policies).
- **One background mode for tasks and shell commands**: `agent.task_execution` and `agent.shell_execution` could make every task or shell command wait or return at once. Both are retired, and Caudra comments them out with the reason. A task or shell command runs in the background when the model passes `background: true`, `/tasks background` still promotes a running task, and `--print` always waits. The SDK `init` message no longer has a `task_execution` object. See [Background tasks](https://caudra.ai/docs/sessions/#background-tasks).
- **Commands guide you through their arguments**: The command list shows each command's arguments, and after the command a list offers values for the slot under the cursor, such as thinking levels, task ids, workflow runs, and docs pages. `Tab` takes the highlighted value, and `Enter` on a mistyped word runs it, so `/thinking hgh` sets `high`. The `Ctrl+P` modal does the same, and Lua plugins add values with the new `complete` option of `register_command`. Commands that were verbs of another command are now its subcommands: `/goal clear`, `/goal model`, `/stash pop`, `/stash list`, `/update dismiss`, `/model next`, `/decisions model`, `/decisions next`, `/sessions move`, `/sessions migrate`, and `/search` in place of `/search-history`. Typing an old name finds the new form. See [Arguments](https://caudra.ai/docs/commands/#arguments).
- **Todo lists stream as the model writes them**: The `todo_write` card and the sticky todo panel show each item as soon as the model starts writing it, instead of the whole list once the call ran. If the call fails or is cancelled, the panel returns to the last stored list. ACP clients get a `plan` update as each item is finished. See [Turn updates](https://caudra.ai/docs/acp/#turn-updates).
- **`/catchup`**: Asks a `/btw` side question that summarizes the session: the goal and where things stand, what needs you, what the agent is doing, and what is done, decided, and still open. Add a few words, such as `/catchup the migration`, to narrow it. Nothing enters history. See [Commands](https://caudra.ai/docs/commands/).
- **`/btw` in task chats**: In a task's chat, `/btw` and `/catchup` now ask about that task's conversation, and `F2` on a question a task asked clarifies it over that task's conversation instead of refusing. See [Commands](https://caudra.ai/docs/commands/).
- **Decision calls are priced**: Calls to a decision endpoint showed in `/usage` without a cost. TypeSafe Jev now costs $0.042 and the OpenAI Decisions API on `gpt-6-luna` $0.10 per 1M input tokens, and output is free on both. Decision spend counts toward the session's cost, goal spend, and Autopilot's `max_cost`, including calls that timed out or were cancelled. Other models, such as a local `decision-1`, stay unpriced. See [Decision prices](https://caudra.ai/docs/providers/#decision-prices).
- **Long background shells ask whether to keep waiting**: Every 30 minutes a background shell runs, Caudra shows the agent waiting on it the latest output and asks whether to keep waiting or cancel, so a command stuck on a prompt or a lock no longer holds the agent until its deadline. Set `agent.shell_wait_nudge_minutes` to change the interval, or to `0` to turn it off. See [Long-running background shells](https://caudra.ai/docs/context/#long-running-background-shells).
- **Shell results say more**: A result now says how long the command ran, such as `[shell status: exit code 0; took 3m12s]`, and a cancelled command reports its output so far instead of only `Shell execution cancelled`. See [shell](https://caudra.ai/docs/tools/#shell).
- **More of the composer can be undone**: Clearing the draft with `Ctrl+C`, completing a command, browsing input history, starting a workflow, and applying a saved draft are now undo steps, and undo brings paste chips back with their content. `Ctrl+Shift+Z` redoes in every text field, and `Super+Z` undoes on terminals that report `Super`. See [Text Fields](https://caudra.ai/docs/keybindings/#text-fields).
- **Recently finished tasks come first**: `/tasks` lists finished subagents newest first, matching `/shells`.

### Fixes

- **Tab completion keeps the rest of the draft**: `Tab` on a command replaced the whole draft with the command name. It now replaces only the command word, so `/goFix the bug` completes to `/goal Fix the bug`. See [Commands](https://caudra.ai/docs/commands/).
- **A goal set during a turn no longer waits in the queue**: `/goal` or `/autopilot <goal>` sent during a turn became a plain queued prompt, which a reopen could send as bare text. The goal now takes effect at once and starts after the current work. See [Send next](https://caudra.ai/docs/queue/#send-next).
- **Reopened sessions hold their queued prompts**: Reopening, resuming, or rewinding a session sent its saved queue at once. Saved prompts now wait under **Held until sent** until you choose **Send now**, edit, or delete them. See [Recovery](https://caudra.ai/docs/queue/#recovery).
- **Long sessions stay responsive**: In a session with many subagents and shell commands, opening a subagent, scrolling `/tasks`, and redrawing got slower the longer it ran. They now stay about as fast as in a new session.
- **Long subagent runs no longer block background results**: A subagent transcript past 8 MiB could not be saved, so Caudra kept showing `Background results could not be saved, retrying` and delivered no more results. Transcripts are now saved in the session database at any size. See [Background tasks](https://caudra.ai/docs/sessions/#background-tasks).
- **A replaced subagent turn can start background work again**: After you replaced a task's turn from its chat, its new background shells and tasks were refused with `background task admission is closed`. They now start. See [Task chats](https://caudra.ai/docs/queue/#task-chats).
- **Database upgrades show progress**: An upgrade names each step with a spinner, where a full progress bar made a long upgrade look frozen.
- **Plan cards no longer flicker**: A plan card's preview briefly disappeared before its result arrived, which made the transcript jump.
- **Update from the banner**: The update banner only named a command to run in another terminal. Clicking it, or running `/update`, now asks whether to update, installs the release in the terminal, where a sudo prompt can reach you, and restarts Caudra on the same tabs with the same flags. Running work is interrupted, and `agent.resume_interrupted` decides whether it resumes. On Windows and in an `--ephemeral` run, Caudra exits instead of restarting. A Homebrew, Nix, or Cargo installation says to update through its package manager. See [ui.update_check](https://caudra.ai/docs/configuration/#ui-update-check).
