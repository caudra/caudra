- Decision calls to TypeSafe Jev and the OpenAI Decisions API count toward your spend in `/usage`, the session's cost, goal spend, and Autopilot's `max_cost`.
- Tasks and shell commands have one way to run in the background, and `agent.task_execution` and `agent.shell_execution` are gone.
- A shell command still running after 10 minutes moves to the background instead of holding up the turn.
- Every 30 minutes a background shell runs, Caudra asks the agent waiting on it whether to keep waiting or check whether the command hangs.
- Clicking the update banner, or running `/update`, installs the new release and restarts Caudra on the same sessions.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 14.** On its first start, Preview 14 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout) to keep each background task's transcript beside its record. While another terminal, editor session over ACP, or `caudra storage` command still has the database open, Preview 14 lists those sessions and does not start. It also moves the global `caudra.toml` to format version 5.
>
> Both upgrades save a copy first: the database as `backups/caudra.db.v38.bak` and `caudra.toml` under `backups/config/global/`, both in the state directory. Preview 13 and earlier cannot open the upgraded database or read the upgraded `caudra.toml`, and `caudra rollback` restores only the previous binary. See [Config file versions](https://caudra.ai/docs/configuration/#config-file-versions).

### Changes

- **Todo lists stream as the model writes them**: A `todo_write` card stayed empty until the call ran, and then the whole list appeared at once. The card and the sticky todo panel now show each item as soon as the model begins writing it. An item shows as pending until its status arrives. If the call fails or is cancelled, the panel returns to the last list a call stored. ACP clients get a `plan` update each time an item is finished. See [Turn updates](https://caudra.ai/docs/acp/#turn-updates).
- **Recently finished tasks come first**: The Finished section in `/tasks` now lists subagents by completion time, newest first, matching `/shells`.
- **Plan cards stay open as execution starts**: Streamed previews no longer briefly disappear before the tool returns its result, preventing the card and surrounding transcript from jumping.
- **Decision calls are priced**: Every call to a decision endpoint was booked in `/usage` and `caudra storage usage` without a cost, so it showed only as an unpriced turn and the decision engine's spend was missing from the total. Calls to TypeSafe Jev (`jev-1.14.0`, `jev-1.13.0`, `jev-latest`, `jev-preview`) now cost $0.042 per 1M input tokens, and calls to the OpenAI Decisions API on `gpt-6-luna` cost $0.10 per 1M input tokens, with cache reads and writes at gpt-6-luna's cache rates and higher rates for prompts past 272K tokens. Output is free on both. The `decision` purpose also splits OpenAI cache reads and writes from the rest of the input. Other models, such as a local `decision-1`, still count as unpriced. Decision spend also counts toward the session's cost, goal spend, and Autopilot's `max_cost`, including refused or invalid answers. A call that timed out or was cancelled keeps reading its reply for up to 30 seconds and books what it cost, and no retry starts after the caller stopped waiting. See [Decision prices](https://caudra.ai/docs/providers/#decision-prices).
- **One background mode for tasks and shell commands**: `agent.task_execution` and `agent.shell_execution` could make every task or shell command wait (`sync`) or return at once (`async`). Both are retired. A task waits unless the model passes `background: true`, and `/tasks background` still promotes a running task. A shell command starts in the background when the model passes `background: true`. `--print` always waits. Caudra comments out both lines with the reason. The SDK `init` message no longer has a `task_execution` object. See [Background tasks](https://caudra.ai/docs/sessions/#background-tasks).
- **Long shell commands move to the background**: A shell call waited for its command to finish, however long that took, unless its requested timeout passed `agent.shell_async_threshold_secs`. A call now waits for up to 10 minutes. A command still running then becomes a background shell job without a restart, the agent gets a receipt with the output so far, filtered like a final result, and the result arrives when the command exits or reaches its `timeoutSec` deadline. `timeoutSec` no longer decides where a command runs. Change the wait with `agent.shell_foreground_limit_secs`. Caudra comments out `agent.shell_async_threshold_secs` with the reason. The SDK `init` message reports `shell_execution.foreground_limit_secs` in place of `async_threshold_secs`. See [Execution policies](https://caudra.ai/docs/sessions/#execution-policies).
- **A cancelled shell command says how far it got**: Cancelling a running `shell` command, with `Esc`, `Ctrl+K` in `/shells`, or `/tasks cancel`, told the agent only `Shell execution cancelled`. The result now also carries the last of the command's output so far, filtered like a final result, so the agent can tell where the command stopped. See [Inspect and control tasks](https://caudra.ai/docs/sessions/#inspect-and-control-tasks).
- **Shell results say how long a command took**: A shell result told the agent the exit code but not how long the command ran, so the agent had no basis for the next run's `timeoutSec` or for starting a long command in the background. A command that ran a second or more now ends with, for example, `[shell status: exit code 0; took 3m12s]`, and a timeout with `timed out after 2m`. See [shell](https://caudra.ai/docs/tools/#shell).
- **A long background shell asks whether to keep waiting**: An agent that started a shell in the background waited for its result, however long it took, so a command that hung on a prompt or a lock held the agent until its `timeoutSec` deadline. Every 30 minutes the command runs, Caudra now sends the agent waiting on it a reminder with the last of its output, filtered like a final result, and asks whether waiting is still necessary or the command should be cancelled. An idle session wakes for it the way it does for a result, and subagents get it too. Foreground commands are never asked about. Change the interval with `agent.shell_wait_nudge_minutes`, or set it to `0` to turn the reminder off. See [Long-running background shells](https://caudra.ai/docs/context/#long-running-background-shells).
- **Update from the banner**: The update banner only named the command to run in another terminal. Clicking its text, or running `/update`, now asks whether to update. Choosing to update stops every session, installs the release in the terminal, where a sudo prompt can reach you, and restarts Caudra on the same tabs with the flags it was started with. Work that was running is interrupted, and `agent.resume_interrupted` decides whether it resumes. If nothing is installed, the sessions reopen with a warning. An `--ephemeral` run, and Windows, where the install finishes after Caudra exits, exit instead of restarting. A Homebrew, Nix or Cargo installation says to update through its package manager. See [ui.update_check](https://caudra.ai/docs/configuration/#ui-update-check).
- **More of the composer can be undone**: Some edits in the composer could not be taken back. Clearing the draft with `Ctrl+C`, a command completion, starting a workflow from `/workflow`, and applying a saved prompt draft replaced the draft and dropped its undo history. Browsing input history with `Up` and `Down` did the same. Undoing the deletion of a paste chip brought back the text `[Pasted 3 lines]` instead of the paste. Each of these edits is now one undo step, the draft keeps its undo history while you browse, and undo and redo bring paste chips back with their content. Attached images are not part of undo. `Ctrl+Shift+Z` now redoes in every text field, and `Super+Z` and `Super+Shift+Z` undo and redo on terminals that report `Super`. See [Text Fields](https://caudra.ai/docs/keybindings/#text-fields).

### Fixes

- **Tab completion keeps the rest of the draft**: Pressing `Tab` on a command replaced the whole composer with the command name, so typing `/` in front of a written prompt and completing the command deleted the prompt and its paste chips. `Tab` and `Enter` now replace only the command word, up to the cursor when the cursor is inside it, and the rest of the draft becomes the command's arguments. `/goFix the bug` completes to `/goal Fix the bug`. Completing a prompt argument from an MCP server replaces only that argument. See [Commands](https://caudra.ai/docs/commands/).
- **A goal set during a turn no longer waits in the queue**: `/goal` or `/autopilot <goal>` sent while Caudra worked became an ordinary queued prompt, and a reopen could later send it as bare text that confused the model. The goal now takes effect at once, and its first turn starts after the current work and any queued prompts are done. See [Send next](https://caudra.ai/docs/queue/#send-next).
- **Reopened sessions hold their queued prompts**: Reopening, resuming, or rewinding a session sent its saved queue at once, so prompts written for a turn that never finished could run without you. Saved prompts now wait under **Held until sent**. Choose **Send now** from a prompt's menu to deliver it, or edit or delete it. A turn started from the queue now also resumes after a crash, like any other turn. See [Recovery](https://caudra.ai/docs/queue/#recovery).
- **Long sessions stay responsive**: In a session with many subagents and shell commands, opening a subagent, scrolling `/tasks`, and redrawing the screen got slower the longer the session ran, until a restart. Caudra now updates task cards and the task list only when a task changed, so these stay about as fast as in a new session.
- **Long subagent runs no longer block background results**: A subagent whose transcript grew past 8 MiB could not be saved when it finished. Caudra then showed `Background results could not be saved, retrying` and never delivered that task's result or any later one. A task's transcript is now saved beside its record in the session database, however long it grows, so the result arrives and the task can still be continued. If background tasks ever stop for good, Caudra says so once and asks you to restart, instead of retrying forever. See [Background tasks](https://caudra.ai/docs/sessions/#background-tasks).
