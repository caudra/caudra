- Decision calls to TypeSafe Jev and the OpenAI Decisions API count toward your spend in `/usage`.
- Tasks and shell commands have one way to run in the background, and `agent.task_execution` and `agent.shell_execution` are gone.
- A shell command still running after 10 minutes moves to the background instead of holding up the turn.

> [!NOTE]
> On its first start, Preview 14 upgrades `caudra.toml` to format 5 and saves a copy under `backups/config/global/` in the state directory. Preview 13 and earlier cannot read the upgraded file. See [Config file versions](https://caudra.ai/docs/configuration/#config-file-versions).

### Changes

- **Decision calls are priced**: Every call to a decision endpoint was booked in `/usage` and `caudra storage usage` without a cost, so it showed only as an unpriced turn and the decision engine's spend was missing from the total. Calls to TypeSafe Jev (`jev-1.14.0`, `jev-1.13.0`, `jev-latest`, `jev-preview`) now cost $0.042 per 1M input tokens, and calls to the OpenAI Decisions API on `gpt-6-luna` cost $0.10 per 1M input tokens, with cache reads and writes at gpt-6-luna's cache rates and higher rates for prompts past 272K tokens. Output is free on both. The `decision` purpose also splits OpenAI cache reads and writes from the rest of the input. Other models, such as a local `decision-1`, still count as unpriced. See [Decision prices](https://caudra.ai/docs/providers/#decision-prices).
- **One background mode for tasks and shell commands**: `agent.task_execution` and `agent.shell_execution` could make every task or shell command wait (`sync`) or return at once (`async`). Both are retired. A task waits unless the model passes `background: true`, and `/tasks background` still promotes a running task. A shell command starts in the background when the model passes `background: true`. `--print` always waits. Caudra comments out both lines with the reason. The SDK `init` message no longer has a `task_execution` object. See [Background tasks](https://caudra.ai/docs/sessions/#background-tasks).
- **Long shell commands move to the background**: A shell call waited for its command to finish, however long that took, unless its requested timeout passed `agent.shell_async_threshold_secs`. A call now waits for up to 10 minutes. A command still running then becomes a background shell job without a restart, the agent gets a receipt with the output so far, filtered like a final result, and the result arrives when the command exits or reaches its `timeoutSec` deadline. `timeoutSec` no longer decides where a command runs. Change the wait with `agent.shell_foreground_limit_secs`. Caudra comments out `agent.shell_async_threshold_secs` with the reason. The SDK `init` message reports `shell_execution.foreground_limit_secs` in place of `async_threshold_secs`. See [Execution policies](https://caudra.ai/docs/sessions/#execution-policies).
- **A cancelled shell command says how far it got**: Cancelling a running `shell` command, with `Esc`, `Ctrl+K` in `/shells`, or `/tasks cancel`, told the agent only `Shell execution cancelled`. The result now also carries the last of the command's output so far, filtered like a final result, so the agent can tell where the command stopped. See [Inspect and control tasks](https://caudra.ai/docs/sessions/#inspect-and-control-tasks).
