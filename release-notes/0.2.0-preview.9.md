- Code mode: the model calls your MCP servers from Python, so a large server costs a short list, results are filtered before the model reads them, and the prompt cache survives.
- Gemini 4 Argon is the Google default, with new Gemini Flash models, Grok 4.7, GLM-5.3, DeepSeek V4.1 Flash, and Mistral Large 4. Retired models are gone, and Google requests work again.
- The agent can ask questions without waiting, and you can answer later.
- Autopilot runs without a continuation limit, answers the agent's questions, and logs what it did.
- A log of every goal check, and goal checks survive an interrupted reply.
- `/worktree close` brings a worktree's work back to the main checkout.
- `/model` opens on your favorites, and `Home` and `End` reach the ends of a list.
- macOS updates no longer stall, and updates use your GitHub token and show download progress.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 9.** On its first start, Preview 9 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout), and the upgrade needs exclusive access. This includes other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 9 does not start. It lists the open sessions to close instead, and nothing is changed.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `caudra.db.v25.bak` next to `caudra.db`. Preview 8 and earlier cannot open the upgraded database, and `caudra rollback` restores only the previous binary, not the database.

> [!WARNING]
> **Before you start Preview 9, delete `defer_tools` and `always_load` from `mcp.toml`.** Code mode replaces the tool search they tuned. A global or project `mcp.toml` that still sets either fails to load: Caudra starts without that file's servers, and `/mcp` shows an error that names the key.

### MCP

- **Code mode.** The model now reaches your MCP servers by writing Python in one `mcp` tool, instead of receiving a definition for every tool. A snippet can call several tools at once and filter or join their results before the model reads anything, so a list of 500 issues can come back as three lines. The model learns your servers from a short list in the conversation, and `search()` finds the tools the list leaves out. The tool definitions stay the same while a server connects, fails, or changes its tools, and when you switch to plan mode, so none of these makes the provider read the whole conversation again at full price. See [Code mode](https://caudra.ai/docs/mcp/#code-mode) and [The prompt cache](https://caudra.ai/docs/configuration/#the-prompt-cache).
- **Approvals work as before.** Each tool call in a snippet asks on its own, and permission rules, `agent.disabled_tools`, and profiles still name a tool `server.tool`. Plan mode and read-only agents still allow only the read-only tools of recognised servers. Snippets run in a separate worker process with no filesystem, network, subprocess, or environment access. See [MCP tool calls](https://caudra.ai/docs/permissions/#mcp-tool-calls) and [Where snippets run](https://caudra.ai/docs/mcp/#where-snippets-run).
- **Snippets are checked before they run.** A misspelt tool, an argument of the wrong type, or code that is not valid Python stops a snippet before any server call, naming the closest tool and the line. Slips with one meaning, such as a missing `import asyncio` or a Markdown fence around the snippet, are fixed and listed on the card. See [Results and errors](https://caudra.ai/docs/mcp/#results-and-errors).
- **`mcp_resource` is gone.** The model reads a server's resources with `resources()` and `read_resource()` in `mcp`, and reads still ask first. See [Resources](https://caudra.ai/docs/mcp/#resources).
- **Servers with a code mode of their own.** Add `?codemode=false` to the URL of Cloudflare's MCP server, or `?mode=passthrough` to Executor's, so the model calls their plain tools. See [Servers with a code mode of their own](https://caudra.ai/docs/mcp/#servers-with-a-code-mode-of-their-own).
- **`/mcp` and `/tools`.** `/mcp` shows the name the model calls each server by, and warns at startup when no code worker can run snippets. `/tools` counts each server call a snippet makes as a row named `server.tool`. See [What the tools cost](https://caudra.ai/docs/token-economy/#what-the-tools-cost).
- **Smaller changes.** Sessions from Preview 8 and earlier resume as before. File revert records an `mcp` run only once it calls a tool that may change files. Python now runs on Monty 1.1.0, which supports complex numbers. See [Recording](https://caudra.ai/docs/sessions/#recording).

### Models

- **Gemini 4 Argon.** `google/gemini-4-argon` is the Google Best model and the model Caudra picks when you use Google without choosing one, in place of `gemini-2.5-pro`. It costs $2 per million input tokens and $10 per million output tokens, with cache reads at $0.10, until November 30, 2026, then $4 and $20 from December 1, 2026. Caudra switches to the new price on that date without an update. Argon always thinks, so thinking `off` runs at `low`. It is not on Google's free tier, so it needs a key on a project with billing enabled. On the free tier, pick `google/gemini-3.8-flash`. When a key has no quota for a model, Caudra now says so at once instead of retrying. Caudra uses an API key for Google, since Google's terms forbid third-party tools from using the sign-in of Gemini CLI or Antigravity. See [Google](https://caudra.ai/docs/providers/#google).
- **Gemini 3.8 Flash, 3.6 Flash, and 3.5 Flash-Lite.** 3.8 Flash and 3.6 Flash cost $0.75 per million input tokens and $3.75 per million output tokens until December 31, 2026, and $1.50 and $7.50 from January 1, 2027. 3.5 Flash-Lite is the Google Fast model, in place of `gemini-2.0-flash-lite`, which Google shut down. Gemini 2.5 Pro and 2.5 Flash leave the model table, since Google no longer serves them to new keys.
- **Google models answer again.** Every request to a Google model failed with `Invalid JSON payload received. Unknown name "$schema"`. Caudra now sends tool definitions in a form Google accepts. Switching to Gemini 3 or 4 in the middle of a turn no longer makes Google refuse the request.
- **Grok 4.7.** `xai/grok-4.7` is the xAI default, in place of `grok-4.6`. It costs $2 per million input tokens and $6 per million output tokens, with cache reads at $0.50. Once a prompt reaches 200,000 tokens, every rate doubles for the whole request, as xAI bills it.
- **GLM-5.3 on Z.AI.** `zai/glm-5.3` is the Z.AI Best model and the default on the pay-as-you-go plan, in place of `glm-5.1`. It costs $1.40 per million input tokens and $4.40 per million output tokens, takes a 1M-token context, and always thinks. The Coding plan keeps `glm-5-code`. `glm-5.3-flash` and `glm-5.3-flashx` join as small models that read images. Caudra now bills `glm-5.2` and `glm-5.1` at Z.AI's current $1.40 and $4.40, up from $1 and $3.20.
- **DeepSeek V4.1 Flash.** `deepseek/deepseek-flash` is the DeepSeek default, in place of the retired `deepseek-v4-flash`. It reads images and costs $0.15 per million input tokens and $0.60 per million output tokens off-peak, twice that at peak hours.
- **Mistral Large 4 and GLM 5.3 on Mistral.** `mistral/mistral-large-4`, in public preview, costs $0.68 per million input tokens and $2.09 per million output tokens at its launch price, and $1.36 and $4.18 from October 20, 2026. `mistral/glm-5-3` replaces `glm-5-2` at the same price. Mistral retires GLM 5.2 on October 31, 2026.
- **Claude Sonnet 4.6 answers at full length.** `anthropic/claude-sonnet-4-6` can now write up to 128,000 output tokens, up from 64,000.
- **Retired models leave the model table.** Caudra drops `claude-sonnet-4`, `claude-opus-4-0`, and `claude-opus-4-1`, which Anthropic retired. Use `claude-sonnet-5-5` or `claude-opus-4-8` instead. It also drops `gpt-5.1-codex`, `gpt-5.1-codex-max`, `gpt-5.1-codex-mini`, and `gpt-5.2-codex`, which OpenAI shut down. Use `openai/gpt-5.6-sol`, or `gpt-5.6-terra` in place of `gpt-5.1-codex-mini`.
- **Copilot follows GitHub's model list.** Copilot and Copilot Enterprise add `gemini-3.8-flash`, `gemini-4-argon`, and `grok-4.7`, and drop the models GitHub no longer serves, such as `gemini-3.5-flash`, `kimi-k2.7-code`, and `claude-opus-4.7`. `claude-sonnet-4.6` stays, because GitHub still serves it on annual Copilot Pro and Pro+ plans.

### Questions

- **Questions that do not stop the agent.** The agent can ask a question it does not need answered for its next steps, such as a preference or a name, and keep working. Press `Esc` to put the form aside in a `[? N]` chip in the footer, and `Ctrl+X u` or a click on the chip brings it back. Your answer reaches the agent when you give it, even after its turn has ended. On a question the agent waits on, `F4` puts it off and lets the agent carry on. Turn this off with `deferred_questions = false` under `[agent]`. See [Deferred questions](https://caudra.ai/docs/sessions/#deferred-questions).

### Autopilot

- **No continuation limit.** `max_continuations = 0` under `[autopilot]` lets an engagement run until its goal ends, its cost or time limit runs out, or you stop it. See [Budgets](https://caudra.ai/docs/autopilot/#budgets).
- **An audit log of what autopilot did.** The status panel gains a Log tab, which `/autopilot log` opens at any time. It lists every decision of the session by engagement, with what the delegate was asked, what autopilot said and why, the model and cost, and what happened next. Press `f` to filter, `y` to copy an entry, and Enter to jump to its row in the transcript. When you answer a decision differently, the delegate sees your answer in its next decisions. SDK clients read the log with the new `autopilot_log` control. See [The log](https://caudra.ai/docs/autopilot/#the-log).
- **Autopilot answers the agent's questions.** While engaged, autopilot now answers the main agent's `question` forms and a server's forms during its tool calls, as Preview 8 described.

### Goals

- **A log of every goal check.** The `/goal` panel gains a Log tab, which `/goal log` opens. It lists every goal of the session and every check of it, with its status, time, evaluator model, cost, and reason. The same keys filter, copy, and jump to the transcript, and a goal's check rows now come back after a resume. SDK clients read the log with the new `goal_log` control. See [The goal log](https://caudra.ai/docs/commands/#the-goal-log).
- **Goal checks survive an interrupted reply.** After you interrupted the agent while it was thinking, every later goal check on a Claude model failed with `thinking.signature: Field required`. Checks now leave out the agent's reasoning, and a goal whose checks were failing is checked normally again.

### Worktrees

- **`/worktree close` brings the work back.** Closing a worktree is the reverse of creating one. It fast-forwards the main checkout's branch to the worktree's commit, moves the worktree's sessions back, carries its uncommitted changes into the main checkout, and removes it, keeping the branch. The removal confirmation offers it first, or says why it cannot, such as when the main checkout has commits of its own. Removing and closing now check for a pending revert or an active workflow before they change anything. Leaving a worktree's own Herdr workspace or Orca terminal brings every open session back, each in its own tab. See [Closing a worktree](https://caudra.ai/docs/worktrees/#closing-a-worktree) and [Removing a worktree](https://caudra.ai/docs/worktrees/#removing-a-worktree).

### Pickers

- **`/model` opens on your favorites.** With favorite models, `/model` and `Ctrl+X m` put the cursor on the current model's favorite row, or on the first favorite, instead of on the Chat job. See [Model jobs](https://caudra.ai/docs/providers/#model-jobs).
- **`Home` and `End` reach the ends of a list.** In every picker, `Home` and `End` jump to the first and last row while the filter is empty. In the workflow and automation inspectors, they and `PageUp` and `PageDown` move the list that has the focus. See [Pickers](https://caudra.ai/docs/keybindings/#pickers).

### Usage

- **Spend by purpose for the session.** `/usage` now shows a Per purpose table for the current session, counted for turns from Preview 9 on. In the lifetime view, click `... and N more` to show the rest of a list, or press `e` to open every list at once. See [Commands](https://caudra.ai/docs/commands/) and [Lifetime spend](https://caudra.ai/docs/token-economy/#lifetime-spend).

### Sessions

- **Tasks run on the favorite you name.** When you ask for a model by a short name, as in "ask sonnet to review this", the task runs on your favorite model that matches it. The main agent is also told your favorites when it can choose a task's model. See [Models and reasoning](https://caudra.ai/docs/commands/#models-and-reasoning).
- **Forks keep their permission mode.** A fork now inherits the parent's Ask, Auto, or YOLO mode, also in another tab or a new worktree.
- **Mode and model switches apply once the session settles.** A `Tab` toggle now takes effect as soon as nothing runs, instead of waiting for your next message. See [Selecting Plan while work runs](https://caudra.ai/docs/queue/#selecting-plan-while-work-runs).
- **`/btw` answers when the model reaches for a tool.** Instead of stopping, Caudra tells the model that tools are unavailable, so it answers from the conversation. See [Commands](https://caudra.ai/docs/commands/).

### Updates

- **Updates on macOS no longer stall.** Updating a Mac that still had the large license bundle from Preview 1 stayed on `downloading caudra …` for about four minutes. It now takes under a second.
- **Updates use your GitHub token.** `caudra update` and the update notice now send `GITHUB_TOKEN` or `GH_TOKEN` to GitHub, as the installer does, so a shared IP no longer fails with `server returned HTTP 403`.
- **Download progress.** The shell installer shows a progress bar for the release archive. From Preview 9 on, `caudra update` downloads the archive itself, shows its size, speed, and time left, and checks it against the release checksums.
