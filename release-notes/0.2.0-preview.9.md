Preview 9 adds Gemini 4 Argon as the Google default, along with Gemini 3.8 Flash, 3.6 Flash, and 3.5 Flash-Lite, brings Argon and 3.8 Flash to Copilot, adds Grok 4.7, GLM-5.3, DeepSeek V4.1 Flash, and Mistral Large 4, drops the Claude, Codex, and Copilot models their providers retired, bills announced price changes from their dates, fixes Google requests, which all failed on Caudra's tool definitions, fixes updates on macOS that sat for minutes on the download line, lets update checks use your GitHub token, shows download progress while Caudra updates, opens `/model` on your favorite models, lets `Home` and `End` jump to the ends of a picker's list, lets the agent ask questions without waiting for the answer and lets you answer a question later, runs a task on the favorite model you name, lets autopilot run without a continuation limit, fixes autopilot never answering the agent's questions, keeps a log of what autopilot did and what happened next, keeps a log of every goal check, lets `/btw` answer when the model reaches for a tool, and breaks `/usage` down by purpose for the session as well as for all time.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 9.** On its first start, Preview 9 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout), and the upgrade needs exclusive access. This includes other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 9 does not start. It lists the open sessions to close instead, and nothing is changed.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `caudra.db.v25.bak` next to `caudra.db`. Preview 8 and earlier cannot open the upgraded database, and `caudra rollback` restores only the previous binary, not the database.

### Models

- **Gemini 4 Argon.** `google/gemini-4-argon` is the Google Best model and the model Caudra picks when you use Google without choosing one, in place of `gemini-2.5-pro`. It costs $2 per million input tokens and $10 per million output tokens, with cache reads at $0.10, until November 30, 2026. Thinking takes `low`, `medium`, and `high`, and thinking `off` runs at `low`, because Argon always thinks. Argon is not on Google's free tier, so it needs a key on a project with billing enabled. On the free tier, pick `google/gemini-3.8-flash`. When Google gives a key no quota for a model at all, Caudra now says so at once instead of retrying for two and a half minutes. Caudra asks for at most 65,536 output tokens, the most one streaming request returns. If you raise `max_output_tokens` past that, an answer Gemini stops at the cap is now reported as cut off instead of complete. See [Google](https://caudra.ai/docs/providers/#google).
- **Gemini 3.8 Flash and 3.6 Flash.** Both cost $0.75 per million input tokens and $3.75 per million output tokens until December 31, 2026. 3.8 Flash takes thinking levels from `low` to `high`, and 3.6 Flash from `minimal` to `high`.
- **Gemini 3.5 Flash-Lite is the Google Fast model.** It replaces `gemini-2.0-flash-lite`, which Google shut down, so session titles, completion-goal checks, and other Fast work on a Google session run on it unless you bound those jobs to a model. Thinking `off` runs at `minimal`.
- **Gemini 2.5 Pro and 2.5 Flash leave Caudra's model table.** Google stopped serving them to new API keys and points to `gemini-3.8-flash` instead. A key that still has them can use them, but Caudra no longer shows their cost.
- **Gemini price changes on their dates.** Argon moves to $4 and $20 per million input and output tokens on December 1, 2026, and 3.8 Flash and 3.6 Flash move to $1.50 and $7.50 on January 1, 2027. Caudra counts each turn at the price in force when it ends, from 00:00 UTC on those days, without an update. The providers page lists both prices with the date.
- **Gemini on Copilot.** Copilot and Copilot Enterprise add `gemini-3.8-flash` and `gemini-4-argon`, at GitHub's introductory prices, and drop `gemini-3.5-flash`, `gemini-3.6-flash`, and `gemini-3.1-pro-preview`, which GitHub no longer serves.
- **Google models answer again.** Every request to a Google model failed with `Invalid JSON payload received. Unknown name "$schema"`, because Caudra's tool definitions name the JSON Schema version they follow, and the field Caudra sent them in refuses it. Caudra now sends tool definitions in the field that takes standard JSON Schema, so MCP tools that use `$ref`, `oneOf`, or `const` work with Google too. It rewrites the few shapes Gemini still refuses, such as a `required` list that names an undeclared property.
- **Gemini 3 and 4 accept tool calls from another model.** Google refuses a request when a tool call in the current turn carries no thought signature, which happened after you switched to Gemini 3 or 4 in the middle of a turn. Caudra now marks such a call the way Google documents, and keeps every signature Gemini issued. Aliases without a version, such as `gemini-flash-latest`, count as current models.
- **Claude Sonnet 4.6 answers at full length.** Caudra now lets `anthropic/claude-sonnet-4-6` write up to 128,000 output tokens, the limit Anthropic documents, instead of 64,000.
- **Retired Claude models leave the model table.** Anthropic retired Claude Sonnet 4 and Claude Opus 4 on June 15, 2026, and Claude Opus 4.1 on August 5, 2026, so Caudra drops `claude-sonnet-4`, `claude-opus-4-0`, and `claude-opus-4-1` from its model table. Use `claude-sonnet-5-5` or `claude-opus-4-8` instead, as Anthropic recommends.
- **Retired Codex models leave the model table.** OpenAI shut down `gpt-5.1-codex`, `gpt-5.1-codex-max`, `gpt-5.1-codex-mini`, and `gpt-5.2-codex` on July 23, 2026, so Caudra drops them too. Use `openai/gpt-5.6-sol`, or `gpt-5.6-terra` in place of `gpt-5.1-codex-mini`.
- **Grok 4.7.** `xai/grok-4.7` is the xAI default, in place of `grok-4.6`, and the model Caudra picks when you use xAI without choosing one. It costs $2 per million input tokens and $6 per million output tokens, with cache reads at $0.50, and from a 200,000-token prompt every rate doubles. Thinking takes `low` to `xhigh`.
- **Copilot follows GitHub's model list.** Copilot and Copilot Enterprise add `grok-4.7`, at $2 per million input tokens and $6 per million output tokens. They drop `kimi-k2.7-code`, `mai-code-1-flash-picker`, `claude-opus-4.7`, `claude-opus-4.6`, `claude-opus-4.5`, and `claude-sonnet-4.5`, which GitHub retired. `claude-sonnet-4.6` stays, because GitHub still serves it on annual Copilot Pro and Pro+ plans.
- **Mistral Large 4 and GLM 5.3 on Mistral.** `mistral/mistral-large-4`, in public preview, costs $0.68 per million input tokens and $2.09 per million output tokens at its launch price, and $1.36 and $4.18 from October 20, 2026, when Caudra switches on its own. `mistral/glm-5-3` replaces `glm-5-2` at the same price. Mistral retires GLM 5.2 on October 31, 2026.
- **DeepSeek V4.1 Flash.** `deepseek/deepseek-flash` is the model Caudra picks when you use DeepSeek without choosing one, in place of `deepseek-v4-flash`, which DeepSeek retired and now serves with V4.1 Flash. It reads images and costs $0.15 per million input tokens and $0.60 per million output tokens off-peak, twice that at peak hours. Caudra bills `deepseek-v4-flash` at the same price, and sends V4.1 Flash the empty reasoning it needs on earlier turns so that thinking requests are not refused.
- **GLM-5.3 on Z.AI.** `zai/glm-5.3`, Z.AI's new flagship, is the Z.AI Best model and the model Caudra picks on the pay-as-you-go plan when you don't choose one, in place of `glm-5.1`. It costs $1.40 per million input tokens and $4.40 per million output tokens, takes a 1M-token context, and always thinks. The Coding plan keeps `glm-5-code`. `glm-5.3-flash` and `glm-5.3-flashx` join as small models that read images. Caudra now bills `glm-5.2` and `glm-5.1` at Z.AI's current $1.40 and $4.40, up from $1 and $3.20.
- **No Google sign-in.** A Google AI Pro or Ultra plan covers AI Studio in the browser, and Google bills API use separately. Google's terms forbid third-party tools from using the sign-in of Gemini CLI or Antigravity, so Caudra uses an API key for Google. The providers page now says so.

### Pickers and lists

- **`/model` opens on your favorites.** With favorite models, `/model` and `Ctrl+X m` put the cursor on the current model's favorite row, or on the first favorite, instead of on the Chat job, so you no longer move past every job row first. Without favorites, the picker opens on Chat as before. See [Model jobs](https://caudra.ai/docs/providers/#model-jobs).
- **`Home` and `End` reach the ends of a list.** In `/model`, `/sessions`, and every other picker, `Home` and `End` jump to the first and last row while the filter is empty. Once you type a filter they move the text cursor again, and `Ctrl+Home` and `Ctrl+End` still jump to the ends. In the workflow and automation inspectors, `PageUp`, `PageDown`, `Home`, and `End` now move the run or automation list while it has the focus, instead of scrolling the detail beside it. See [Pickers](https://caudra.ai/docs/keybindings/#pickers).

### Usage

- **Spend by purpose for the session.** `/usage` now shows a Per purpose table for the current session too, beside Per model: what went to the conversation and what to titles, goal checks, compaction, memory summaries, and Caudra's other work. A session counts purposes for turns from Preview 9 on. See [Commands](https://caudra.ai/docs/commands/).
- **Purposes show in full.** The lifetime view cut Per purpose off after 8 rows, so a ninth purpose hid behind `... and 1 more`. Purposes now always show whole, and no list hides a single row behind a line of its own.
- **Long lists open in place.** In the lifetime view, click `... and N more` under providers, models, projects, or months to show the rest, and `show less` to fold it again. Press `e` to open or close every list at once. See [Lifetime spend](https://caudra.ai/docs/token-economy/#lifetime-spend).

### Questions

- **Questions that don't stop the agent.** The agent can ask a question that it doesn't need answered for its next steps, such as a preference or a name, and keep working. The form docks as usual. Press `Esc` to put it aside: it waits in a `[? N]` chip in the footer that counts unanswered questions, and `Ctrl+X u`, for unanswered, or a click on the chip brings it back with what you had picked. Your answer reaches the agent when you give it, even after the agent has finished its turn, and the oldest open question docks again when the agent goes idle. Up to three can be open at once, `F4` moves to the next, and `/tasks` lists them as waiting for your answer. Turn this off with `deferred_questions = false` under `[agent]`. See [Deferred questions](https://caudra.ai/docs/sessions/#deferred-questions).
- **Answer later.** On a question the main agent waits on, `F4` puts it off: the agent gets a receipt instead of an answer and carries on, and the form waits off the dock with your picks until you answer it. `Ctrl+C` on any question still stops the run, and stopping the run withdraws its open questions.

### Tasks

- **Tasks run on the favorite you name.** When you ask for a model by a short name, as in "ask sonnet to review this", the task now runs on your favorite model that matches the name, even when a newer model or another provider matches too. While the main agent can choose a task's model, it is also told your favorites with their lane, the jobs you bound to them, and the thinking levels they take, and hears again when you star or unstar one. See [Models and reasoning](https://caudra.ai/docs/commands/#models-and-reasoning).

### Autopilot

- **No continuation limit.** `max_continuations = 0` under `[autopilot]` lets an engagement run until its goal ends, its cost or time limit runs out, or you stop it, so a session that an automation keeps busy every day can stay on autopilot. The footer chip then shows the count without a limit, and SDK clients read `max_continuations` as `null`. See [Budgets](https://caudra.ai/docs/autopilot/#budgets).
- **An audit log of what autopilot did.** The status panel gains a Log tab, which `/autopilot log` opens at any time, engaged or not. It lists every decision of the session under its engagement, with what the delegate was asked, such as the exact command of a permission request, what autopilot said, its reason, the model and cost, and what happened next: whether the action applied, you answered first, you took the card, or you answered after autopilot left it to you. Press `f` to filter, `y` to copy an entry, and Enter to jump to its row in the transcript. Click a decision row in the transcript to see what autopilot said and what happened next, and the start and end of each engagement come back when you resume. Before, the panel showed only the last 20 decisions of the running engagement in one line each, and a decision row kept only the action's name. Decisions made before Preview 9 keep their one-line record. SDK clients read the log with the new `autopilot_log` control, and `decided`, `engaged`, and `ended` events carry the new fields. See [The log](https://caudra.ai/docs/autopilot/#the-log).
- **Autopilot answers the agent's questions.** While engaged, autopilot never answered a `question` form from the main agent, or a server's form during one of its tool calls, so they always waited for you. It now answers them, as Preview 8 described.
- **The delegate sees your overrides.** When you answered a decision differently from autopilot, the delegate's next decisions see your answer, so it can follow your lead.

### Goals

- **A log of every goal check.** The `/goal` panel gains a Log tab, which `/goal log` opens. It lists every goal of the session and every check of it, with when it ran, how long it took, its status, the evaluator model, its cost, and its reason. Besides met, not met, and impossible, a check can read as reconsidered when a second opinion overruled an impossible verdict, failed, skipped by the goal prescreen, deferred, or stale when the goal changed while it ran. Press `f` to filter, `y` to copy an entry, and Enter to jump to its row in the transcript. Before, the panel showed only the latest verdict, and the transcript rows of a goal's checks were gone after a resume. They now come back. SDK clients read the log with the new `goal_log` control, and goal events carry each check's `seq`, goal number, and times, with a new `skipped` event. See [The goal log](https://caudra.ai/docs/commands/#the-goal-log).

### Side questions

- **`/btw` answers when the model reaches for a tool.** A model that tried to call a tool in `/btw` used to stop with `Stopped: the model tried to call a tool`, often before it had said anything. Caudra now tells it that tools are unavailable and asks again, so it answers from the conversation and says what it could not confirm. It stops only if the model keeps calling tools after two reminders. See [Commands](https://caudra.ai/docs/commands/).

### Command line

- **Updates on macOS no longer stall.** Updating a Mac that still had the large license bundle from Preview 1 stayed on `downloading caudra …` for about four minutes. The installer checks the previous bundle before replacing it, and its JSON reader grew slower with every character of that bundle's 2 MB manifest under the `awk` that ships with macOS. It now reads the manifest in under a second, and a fresh install reads the GitHub release list faster too.
- **Updates use your GitHub token.** `caudra update` and the update notice now send `GITHUB_TOKEN`, or `GH_TOKEN`, when they ask GitHub for releases, the same as the installer. Behind a shared IP that had used up GitHub's unauthenticated quota, they failed with `server returned HTTP 403`. Without a token, that refusal now says to set one, in `caudra update` and in both installers.
- **Download progress.** The shell installer shows curl's progress bar for the release archive when it runs in a terminal, so updating to Preview 9 shows it already. From Preview 9 on, `caudra update` downloads the archive itself and shows a bar with size, speed, and time left. It checks the archive against the release checksums before it saves your current version, and if the download fails, the installer downloads the archive instead.
