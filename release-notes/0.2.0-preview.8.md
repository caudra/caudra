Preview 8 lets the experimental decision engine rerank memory notes, tool search, retained tool output, and code context, shows in the transcript what each decision feature changed, gives workflows a `rerank()` function, opens forks in a new Herdr or Orca tab, names tabs after the session, makes the wheel scroll lists instead of moving their selection, and stops pending reverts in a destination directory from blocking session moves.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 8.** On its first start, Preview 8 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout), and the upgrade needs exclusive access. This includes other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 8 does not start. It lists the open sessions to close instead, and nothing is changed.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `caudra.db.v24.bak` next to `caudra.db`. Preview 7 and earlier cannot open the upgraded database, and `caudra rollback` restores only the previous binary, not the database.

> [!NOTE]
> **If you raised `decisions.timeout_ms` for a slow decision engine and use `tool_search`, set `rerank_timeout_ms` as well.** Tool search now uses that deadline, which defaults to 2 seconds.

### Decision engine

- **Reranking features.** Six new experimental decision features use the engine as a reranker, and each is off by default. `memory_search` shows the memory search matches the engine judges relevant, best first, and names the ones it left out. `memory_recall` reminds the agent of up to three notes that may matter for your new message. `memory_duplicates` points out an existing note when a new one may repeat it. `compaction_retention` keeps the tool results that matter to the current goal, todos, and request when a session compacts, instead of only the newest three. `output_pointers` adds up to two lines to a truncated tool result that point at the omitted lines most likely to matter, with the `tool_output` call that reads them. `code_context` moves the most relevant rows of a `code_context` result to the top. Each asks one true or false question per candidate, up to 16 per request, with redacted and bounded candidate text. When the engine fails or times out, each behaves as if it were off. A new `rerank_timeout_ms` deadline (2 seconds) and `thresholds.relevance_floor` (`0.1`) apply to them. See [Reranking](https://caudra.ai/docs/configuration/#reranking).
- **Tool search judges each candidate.** With `tool_search` enforced, the engine now scores each of the first 16 keyword matches instead of picking one from the whole list. It reorders them and never drops one. On the local evaluation set it got one more query right than the single pick, with no new wrong answers, at about 130 ms more per search.
- **Workflows can rerank.** `rerank(query, candidates)` and `rerank(query, candidates, opts)` return `#{ index, score }` entries, most relevant first. Options are `model`, `timeout_ms`, `threshold`, and `top_k`. Each batch of 16 candidates is one journaled decision, so a resumed run asks only for the rest. A `decide()` or `rerank()` timeout may now reach the larger of `timeout_ms` and `rerank_timeout_ms`. See [Reranking candidates](https://caudra.ai/docs/workflows/#reranking-candidates).
- **Decision rows in the transcript.** When a decision feature changes what happens, the transcript shows one row that names the feature and what it did, such as `code_context · moved 3 of 12 rows up`, placed after the tool call or at the turn it affected. A row also appears when the engine fails and the default applies, once per feature until the engine answers again, and a dim `shadow` row shows what a feature in shadow mode would have done. Click a row to see the candidates and scores behind it. The rows are saved with the session and return in place when you reopen it. The model never sees them, and `[ui] show_decisions = false` hides them. See [Decision rows](https://caudra.ai/docs/permissions/#decision-rows-in-the-transcript).
- **Workflow decisions are labelled.** In `/workflow`, a `decide()` call now reads like `decide: ready, route` and a `rerank()` batch like `rerank: 17 candidates · batch 2 of 2`, instead of a bare call number. Labels hold only question IDs and counts, never the state or candidates.

### Interface fixes

- **The wheel scrolls lists.** In `/decisions`, `/automations`, `/workflow`, `/peers` and `/messages`, the wheel over the list now scrolls it instead of moving the selection and loading every row it passes. Click a row or use the arrow keys to select one.

### Sessions

- **Tabs are named after the session.** Caudra sets the terminal window title to the title of the focused session, so most terminals and Orca label the tab with it until you name the tab yourself. Inside Herdr, Caudra renames the tab while it still shows its number, and again when the session title changes, as long as the tab still shows the title Caudra gave it. A tab you named keeps its name. On exit, a terminal with a title stack gets its earlier window title back. Herdr cannot clear a tab name, so the tab keeps the last session title. A plugin that sets the window title keeps it from then on. See [Tab names](https://caudra.ai/docs/sessions/#tab-names).
- **Forks open in a new Herdr or Orca tab.** Inside a Herdr pane or an Orca terminal, **Fork here** saves the new session and resumes it in a new tab of that host, with a Caudra of its own. The tab takes focus and the session you forked from stays open where it was. Remote, sandbox, and ephemeral sessions still fork into a tab of the current Caudra, and so does a fork the host cannot open. See [Forks in Herdr and Orca](https://caudra.ai/docs/sessions/#forks-in-herdr-and-orca).
- **Moving into a directory ignores its pending reverts.** A move was refused with "Destination session … has a pending restore; resolve it before moving sessions" when any session already in the destination had a pending revert, even an old conversation revert. `/move-session` and `/migrate-sessions` stopped there. `/worktree remove` and other moves that brought this Caudra back to such a directory committed the move and then failed to start, with "UI startup failed; reopen the committed sessions at the destination". Sessions already in the destination no longer affect a move, just as they never stopped a new session from starting there. The rules for the directory a session leaves are unchanged.
