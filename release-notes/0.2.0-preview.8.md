Preview 8 adds Claude Haiku 5.5 as the Anthropic Fast model, lets the experimental decision engine rerank memory notes, tool search, retained tool output, and code context, shows in the transcript what each decision feature changed, gives workflows a `rerank()` function, runs a task on the model you name, opens forks in a new Herdr or Orca tab, names tabs after the session, lets new sessions open in build mode, makes the wheel scroll lists instead of moving their selection, and stops pending reverts in a destination directory from blocking session moves.

> [!IMPORTANT]
> **Close every other Caudra session before you start Preview 8.** On its first start, Preview 8 upgrades the session database in your [state directory](https://caudra.ai/docs/configuration/#directory-layout), and the upgrade needs exclusive access. This includes other terminals, editor sessions over ACP, and `caudra storage` commands. While any of them still has the database open, Preview 8 does not start. It lists the open sessions to close instead, and nothing is changed.
>
> The upgrade keeps your sessions and saves a copy of the database from before it as `caudra.db.v24.bak` next to `caudra.db`. Preview 7 and earlier cannot open the upgraded database, and `caudra rollback` restores only the previous binary, not the database.

> [!NOTE]
> **If you raised `decisions.timeout_ms` for a slow decision engine and use `tool_search`, set `rerank_timeout_ms` as well.** Tool search now uses that deadline, which defaults to 2 seconds.

### Models

- **Claude Haiku 5.5.** `anthropic/claude-haiku-5-5` costs $0.10 per million input tokens and $0.50 per million output tokens, with cache reads at $0.01. Once a prompt passes 100k tokens, cached tokens included, Anthropic bills the whole request at five times those rates, and Caudra counts its cost the same way. Caudra runs it at the 372k working window of other recent Claude models, and `claude-haiku-5-5-1m` opens the full 1M window. Thinking takes effort levels from `low` to `max`, and thinking `off` turns its reasoning off. Copilot and Copilot Enterprise list it as `claude-haiku-5.5`. There, as with Copilot's other Claude models, `off` runs at the lowest level. See [Anthropic](https://caudra.ai/docs/providers/#anthropic).
- **Haiku 5.5 is the Anthropic Fast model.** It replaces `claude-haiku-4-5` as the curated Fast model, so on an Anthropic session, session titles, completion-goal checks, and other Fast work run on it unless you bound those jobs to a model. Bind Fast to `anthropic/claude-haiku-4-5` in `/model` to keep the older model. See [Model jobs](https://caudra.ai/docs/providers/#model-jobs).
- **Sonnet 5.5 cache reads cost less.** Anthropic halved the cache read price of Claude Sonnet 5.5 to $0.10 per million tokens, and Copilot bills the same. Caudra now counts `claude-sonnet-5-5` and `copilot/claude-sonnet-5.5` at the new price.

### Decision engine

- **Reranking features.** Six new experimental decision features use the engine as a reranker, and each is off by default. `memory_search` shows the memory search matches the engine judges relevant, best first, and names the ones it left out. `memory_recall` reminds the agent of up to three notes that may matter for your new message. `memory_duplicates` points out an existing note when a new one may repeat it. `compaction_retention` keeps the tool results that matter to the current goal, todos, and request when a session compacts, instead of only the newest three. `output_pointers` adds up to two lines to a truncated tool result that point at the omitted lines most likely to matter, with the `tool_output` call that reads them. `code_context` moves the most relevant rows of a `code_context` result to the top. Each asks one true or false question per candidate, up to 16 per request, with redacted and bounded candidate text. When the engine fails or times out, each behaves as if it were off. A new `rerank_timeout_ms` deadline (2 seconds) and `thresholds.relevance_floor` (`0.1`) apply to them. See [Reranking](https://caudra.ai/docs/configuration/#reranking).
- **Tool search judges each candidate.** With `tool_search` enforced, the engine now scores each of the first 16 keyword matches instead of picking one from the whole list. It reorders them and never drops one. On the local evaluation set it got one more query right than the single pick, with no new wrong answers, at about 130 ms more per search.
- **Workflows can rerank.** `rerank(query, candidates)` and `rerank(query, candidates, opts)` return `#{ index, score }` entries, most relevant first. Options are `model`, `timeout_ms`, `threshold`, and `top_k`. Each batch of 16 candidates is one journaled decision, so a resumed run asks only for the rest. A `decide()` or `rerank()` timeout may now reach the larger of `timeout_ms` and `rerank_timeout_ms`. See [Reranking candidates](https://caudra.ai/docs/workflows/#reranking-candidates).
- **Decision rows in the transcript.** When a decision feature changes what happens, the transcript shows one row that names the feature and what it did, such as `code_context · moved 3 of 12 rows up`, placed after the tool call or at the turn it affected. A row also appears when the engine fails and the default applies, once per feature until the engine answers again, and a dim `shadow` row shows what a feature in shadow mode would have done. Click a row to see the candidates and scores behind it. The rows are saved with the session and return in place when you reopen it. The model never sees them, and `[ui] show_decisions = false` hides them. See [Decision rows](https://caudra.ai/docs/permissions/#decision-rows-in-the-transcript).
- **Workflow decisions are labelled.** In `/workflow`, a `decide()` call now reads like `decide: ready, route` and a `rerank()` batch like `rerank: 17 candidates · batch 2 of 2`, instead of a bare call number. Labels hold only question IDs and counts, never the state or candidates.
- **Shell duration estimates read plainly.** With `shell_duration` set to `advise` or `enforce`, a shell card's header read like `ETA 1–1s (engine prior; 0 samples)`. It now shows an estimate only for a command expected to take more than a second, in the same units as the timeout beside it, such as `ETA 10s–2m`, and leaves out where the estimate came from. Decision rows still name the source, without a count for an engine estimate.

### Tasks

- **Run a task on a model you name.** Ask for a model, as in "ask opus and sol to review this change", and the main agent starts the task on it, with one task per model when you name several. The `task` tool takes a `model`, either an exact `provider/model` name or a short name such as `opus` or `gpt-6.1-sol` that resolves to the newest match you can use, so `opus` picks `claude-opus-5-5`, and a `thinking` level from `off` to `max`. Both win over a profile's `subagent_model` and `subagent_thinking`, and every result reports the model and level the task ran on. A name that fits several models fails and lists them. `[agent] task_model_choice = false` turns this off. See [Models and reasoning](https://caudra.ai/docs/commands/#models-and-reasoning).

### MCP

- **The current MCP protocol.** Caudra now speaks MCP `2026-07-28` and still speaks the older protocol that starts with `initialize`, so servers built on either work. It asks each server which versions it supports when it connects. See [Protocol versions](https://caudra.ai/docs/mcp/#protocol-versions).
- **Servers can ask you questions.** A server can ask for input during a tool call, with a form of typed fields or a link to open, such as a sign-in page. The question form shows it with the server's name, checks each answer against the server's limits, and lets you review before sending. `F3` declines and `Esc` cancels. A link opens in your browser only after you agree, and the form warns about lookalike characters in its host. ACP clients that support MCP elicitation get the question, and print and SDK sessions tell the server they cannot ask. While autopilot is engaged, it may answer a form from the main agent's call, but never a link, a form from Executor, or a form asking for a credential. See [Server questions](https://caudra.ai/docs/mcp/#server-questions).
- **Long calls report progress.** A server's progress shows beside the card's label, and each report restarts the `timeout` wait, up to ten times `timeout`. Stopping the run tells the server the call was cancelled. A dropped connection resends only requests that are safe to repeat. Other tool calls fail with `connection lost; the call's outcome is unknown`. See [Long calls](https://caudra.ai/docs/mcp/#long-calls).
- **Tool lists stay current.** When a server announces that its tools, prompts, or resources changed, Caudra lists them again, and the model sees the change on its next request. Long lists are read page by page.
- **Resources and completions.** Mention a server's resource as `@server:uri`, and Caudra reads it when you send the message and adds it the way it adds a mentioned file. Typing `@` lists the resources and templates of running servers beside your files, and a server that offers completions suggests the values a template needs. The model can list and read resources with the new `mcp_resource` tool, which works in plan mode and asks first, with an option to always allow reads from that server. Prompt arguments complete from the server as you type, and a prompt's images and embedded resources now reach the model. See [Resources](https://caudra.ai/docs/mcp/#resources).
- **Server instructions reach the model.** The instructions each running server gives for its tools are added to the system prompt, up to 4096 bytes per server. See [Server instructions](https://caudra.ai/docs/mcp/#server-instructions).
- **Executor and Home Assistant are recognised.** Executor gets a card that shows how a run ended, its logs, and what a paused run waits for. An Executor `resume` call that approves a paused run always asks you, even under autopilot, and shows what the run waits for. Add `?elicitation_mode=native` to Executor's URL so it asks you directly. Home Assistant gets cards for intents and for its live context, and a call that controls a `lock`, `alarm_control_panel`, `cover`, or `valve` always asks, even with an allow rule or in Auto. See [Recognised servers](https://caudra.ai/docs/mcp/#recognised-servers).
- **Read-only tools work in plan mode.** Tools that Executor or Home Assistant mark read-only, such as Home Assistant's `GetLiveContext`, are low risk and can be called in plan mode and by read-only agents. They still ask, and the prompt offers to always allow the tool with any arguments, for the conversation, the project, or all projects. See [MCP tool calls](https://caudra.ai/docs/permissions/#mcp-tool-calls).
- **MCP cards open whole.** A finished MCP call's card shows its arguments and its whole result rather than the first three rows, and a read-only call's card stays open after newer calls. In the auto view a click folds it to its header. Compact view and `ui.always_collapsed` still fold it. See [Results in the transcript](https://caudra.ai/docs/mcp/#results-in-the-transcript).
- **MCP cards can show the raw result.** An Executor or Home Assistant card drawn its own way, or a card whose `structuredContent` no text block repeats, ends with a `click for raw` row. The raw view shows the result's JSON indented and coloured, other text as the server wrote it, and the `structuredContent` under its name. Click again to return to the card. See [Results in the transcript](https://caudra.ai/docs/mcp/#results-in-the-transcript).
- **Server errors show as failed cards.** A result a server marks as an error draws its card as failed, keeps the server's content, and lists any questions asked during the call. The model reads the same error text as before.
- **`/mcp` shows what a server reported.** Select a running server to see its name and version, the protocol version, the features it offers, and the first lines of its instructions. Recognised servers show their kind, and an Executor server in model mode shows how to switch it to native mode. The details area keeps the height of the longest server's details, so moving through the list no longer resizes the picker. See [Runtime toggling](https://caudra.ai/docs/mcp/#runtime-toggling).
- **A sign-in the server refuses is reported.** `caudra mcp auth` now checks that the server accepts the stored sign-in, and signs in again when it does not. When a fresh sign-in is still refused, as on Home Assistant's `/api/mcp` for a user who is not an administrator, the command fails and `/mcp` shows the server as Refused instead of asking you to sign in again. Home Assistant's `/api/mcp/assist` works for any user. See [OAuth](https://caudra.ai/docs/mcp/#oauth).
- **Deprecated features are refused.** Caudra never offers roots, sampling, or logging to a server. It refuses roots and sampling requests and writes log messages to `caudra.log` at debug level.

### Interface fixes

- **The wheel scrolls lists.** In `/decisions`, `/automations`, `/workflow`, `/peers` and `/messages`, the wheel over the list now scrolls it instead of moving the selection and loading every row it passes. Click a row or use the arrow keys to select one.
- **`minimal` no longer turns reasoning off.** On a model whose lowest level is `none`, such as several OpenAI models and local servers that declare `none`, asking for `minimal` thinking sent `none` and the model did not reason at all. It now sends the shallowest level the model has, usually `low`. Asking for `off` still sends `none`.
- **Copilot no longer sends `none` to a model that always reasons.** On Copilot and Copilot Enterprise, thinking `off` on a model that cannot turn reasoning off, such as `gpt-6.1-sol`, could send `none`, and the request failed with `Unsupported value: 'none' is not supported`. Copilot's model list replaced Caudra's own levels for the model, so a list that offered `none`, or offered no levels at all, decided what was sent. Caudra now keeps its own levels when the list offers none, and never sends `none` to a model its table says always reasons. Such a model runs at its lowest level instead. A `none` thinking setting now means the same as `off` on every model.
- **Custom OpenAI-compatible models without declared levels take no thinking setting.** On an `openai` or `openai-responses` provider in `providers.toml`, a model that declares no `reasoning_options` was offered thinking levels it was never sent, so the footer and task results named a level that did not apply, and an `openai-responses` endpoint was sent the level as typed. Such a model now takes no thinking setting and shows none. Declare its levels with `reasoning_options` to offer them. See [Model defaults](https://caudra.ai/docs/providers/#model-defaults).
- **Prompts, popups and scrollbars follow the theme.** Some surfaces were drawn in the terminal's own background and text colours instead of the theme's, so a dark theme on a light terminal showed light patches. The affected surfaces were the permission prompt, the `@` and `#` completion lists, the sandbox manager, every scrollbar thumb, and the space beside the permission prompt and the question form over the workbench. They now use the theme's colours and change with it when the theme switches between dark and light.
- **A task's footer names the model it runs on.** The footer of a task's chat could show the main session's model instead of the task's, and the task's card in the transcript then named no model. The footer now shows the model and thinking level the task actually runs on, and the card names that model, including one picked by a profile pin or subagent routing.

### Sessions

- **Open new sessions in build mode.** Set `default_mode = "build"` under `[ui]` to start new terminal UI sessions in build mode instead of plan mode. A resumed session still reopens in the mode it was left in, and `/new` in an idle tab keeps that tab's mode. On a fresh start, Caudra also picks the model you last used in that mode. `--print` and ACP already start in build. See [`ui`](https://caudra.ai/docs/configuration/#ui).
- **Tabs are named after the session.** Caudra sets the terminal window title to the title of the focused session, so most terminals and Orca label the tab with it until you name the tab yourself. Inside Herdr, Caudra renames the tab while it still shows its number, and again when the session title changes, as long as the tab still shows the title Caudra gave it. A tab you named keeps its name. On exit, a terminal with a title stack gets its earlier window title back. Herdr cannot clear a tab name, so the tab keeps the last session title. A plugin that sets the window title keeps it from then on. See [Tab names](https://caudra.ai/docs/sessions/#tab-names).
- **Forks open in a new Herdr or Orca tab.** Inside a Herdr pane or an Orca terminal, **Fork here** saves the new session and resumes it in a new tab of that host, with a Caudra of its own. The tab takes focus and the session you forked from stays open where it was. Remote, sandbox, and ephemeral sessions still fork into a tab of the current Caudra, and so does a fork the host cannot open. See [Forks in Herdr and Orca](https://caudra.ai/docs/sessions/#forks-in-herdr-and-orca).
- **Memory writes wait out a busy database.** The `memory` tool failed with `memory journal database operation failed: database is locked` when another Caudra process held the database's write lock for more than 5 seconds, such as while saving a large session. Memory writes, and the background work that builds memory summaries, now keep retrying for up to 30 seconds, like session saves do. A write that times out changes nothing, so it is safe to retry.
- **Moving into a directory ignores its pending reverts.** A move was refused with "Destination session … has a pending restore; resolve it before moving sessions" when any session already in the destination had a pending revert, even an old conversation revert. `/move-session` and `/migrate-sessions` stopped there. `/worktree remove` and other moves that brought this Caudra back to such a directory committed the move and then failed to start, with "UI startup failed; reopen the committed sessions at the destination". Sessions already in the destination no longer affect a move, just as they never stopped a new session from starting there. The rules for the directory a session leaves are unchanged.
