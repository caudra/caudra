- JavaScript and TypeScript `code` snippets run as Python when every part of them translates without changing what it does.
- A stray indent no longer makes a server call in a `code` snippet run every time.
- pstack picks its models from your favorites and model jobs, and its model roles are a tab in `/settings`.
- TLA+, PlusCal and TLC config files are highlighted.
- `file_index` outlines TLA+ specs, and the code tools follow calls between their operators.
- Mermaid state diagrams, such as the charts pstack's statechart tool writes, are drawn in the chat.
- pstack's statechart skill is built in, as `pstack.statechart` in `code`, and needs no Node, Java, or TLC.
- Memory recall reads what you are working on, runs again as the work moves on, reaches subagents, and has its own threshold.
- Decision waits show a spinner and a timer.
- `/fork` forks the session without picking a message.
- A task chat can replace the child's current turn, as the main chat can.

> [!IMPORTANT]
> pstack no longer reads `~/.config/caudra/pstack/models.md`, and its `setup-pstack` skill is gone. If you wrote that file, choose your models again in `/settings` → **pstack**, then delete the file.

### Changes

- **pstack's statechart runs without Node or Java**: `/pstack:statechart` told the agent to download its scripts and run them with Node, and to check the spec with TLC, which needs Java. It is now `pstack.statechart(...)` in the `code` tool, with the same `from-spec` and `from-chart` commands and flags, plus `compare` for two charts. It checks the spec with tla-checker inside Caudra. A spec's mapping is now a Rhai `SPEC.map.rhai` instead of a JavaScript `SPEC.map.mjs`, and charts are Mermaid `.mmd` only, so `--png` is gone. A run replaces its whole output folder, and refuses a folder holding files it did not write. Plan mode refuses `from-spec` and `from-chart`, which write files, and runs `compare` and `--help`. See [pstack scripts](https://caudra.ai/docs/code/#pstack-scripts).
- **pstack chooses models you can run**: pstack's pages named Claude Opus and Grok for every role, so a session without Grok had its tasks rejected, and a review panel meant to compare two models ran one model twice. The pages now name six kinds of work, such as Code, Judgment and Panel, and each page that starts tasks ends with a **Model roles** table of ready `task` arguments. Unless you choose otherwise, code work runs on your Subagent model, judgment on your newest flagship favorite, and a panel on flagship favorites from different providers. Without favorites, judgment and panels take the flagship Caudra starts on for each provider you are signed in to, such as Claude Opus, never a pricier model such as Fable. The **pstack** tab in `/settings` sets a kind's model and thinking, saved with your model jobs. A saved model you can no longer use falls back to the automatic choice, and the table says so. See [Model roles](https://caudra.ai/docs/skills/#model-roles).
- **JavaScript snippets run as Python**: A `code` snippet written in JavaScript or TypeScript, such as `const r = await Promise.all([...]); return r.map(x => x.name)`, was rejected with `This looks like JavaScript`, which cost the model a turn to rewrite it. Caudra now translates it to Python and runs that, when every part has a Python form that keeps its meaning. The card and the model see the Python that ran. A snippet with a part that has no such form, such as `switch`, `if (items)` on a bare value, or a server call that is never awaited, is still rejected, and the error names that part and its line. See [Results and errors](https://caudra.ai/docs/mcp/#results-and-errors).
- **TLA+ highlighting**: `.tla` files and `tla` code blocks were shown as plain text. They are now highlighted as TLA+, with PlusCal inside `(* --algorithm ... *)` comments highlighted as PlusCal, in the chat and the workbench. TLC model configs are highlighted in `tlacfg` code blocks; `.cfg` files stay INI, since other tools use that extension too.
- **TLA+ in the code tools**: `file_index` refused `.tla` files. It now outlines a spec's modules, `EXTENDS` and `INSTANCE`, `CONSTANTS` and `VARIABLES`, operator and function definitions, theorems and assumptions, and a PlusCal algorithm's procedures, processes and labels. `source_code_context` and `source_code_refs` see its operators, constants and variables, and count each name an expression uses as a call, so `source_code_refs` on an action finds the `Next` that takes it. See [Code Intelligence](https://caudra.ai/docs/tools/#code-intelligence).
- **Mermaid state diagrams are drawn**: A ```` ```mermaid ```` block holding a `stateDiagram` or `stateDiagram-v2`, such as a chart from pstack's statechart tool, was shown as code. It is now drawn like a flowchart, with `●` and `◉` for start and end, a dashed frame for each composite state and each of its concurrent regions, and transition labels on their arrows. A transition from a state back to itself, in either kind of diagram, is drawn as a hook beside the state instead of leaving the whole diagram as code. Front matter is skipped. Forks and joins still fall back to code. See [Diagrams](https://caudra.ai/docs/markdown/#diagrams).
- **`/fork` forks the session**: Forking needed the `⋮` menu on a message. `/fork` now copies the session into a new one at its latest message, the same as **Fork here** on that message, and opens it like any fork, in a new tab inside Herdr or Orca. While a turn is running, the fork stops before the prompt that started it, leaves the running turn alone, and puts that prompt in the new session's composer. See [Message actions](https://caudra.ai/docs/sessions/#message-actions).
- **Memory recall follows the work**: `memory_recall` judged notes against your message alone, so "commit this" or "go" could name notes about other tasks, and it ran only at the start of a turn in the main session. It now also sends the todo in progress, up to 3 open todos, and the previous request when yours is short. It runs again when a todo step starts, when a goal check finds the goal unmet, and after compaction; a step or a goal check waits at least 5 model requests after the previous recall. The notes it weighs are chosen with rare words counting for more than common ones and a word matching its other forms, such as "resizing" and "resize", leaving out notes the conversation already read. Subagents recall too, without a memory view in their prompt. Recall has its own `thresholds.recall_confidence`, default `0.75`, instead of `routing_confidence`. See [Relevance from the decision engine](https://caudra.ai/docs/memory/#relevance-from-the-decision-engine).
- **Decision waits show a timer**: Memory recall, skill suggestions, the goal prescreen, the question nudge, and compaction retention waited on the decision engine with nothing on screen, and their rows appeared only when they acted. Each now shows a chip at the right edge of the message, todo card, goal check, or compaction notice that started it, with a spinner and the time so far, and the chips on tool cards, such as reranking and screening, count up the same way. A decision that changed nothing leaves a dim `checked` chip, so the transcript never jumps. Click a chip for the details, including the notes or skills that came closest to the threshold. Once settled, a chip keeps its time for the rest of the session. See [Decision engine](https://caudra.ai/docs/configuration/#decisions).
- **Replace a task's turn from its chat**: A task chat could only guide the child, so a task heading the wrong way kept going until it finished or you cancelled it. `Ctrl+X x`, the `replace` control, `r` on a guidance row, or **Replace current run** in its menu now stops the child's current turn, including its tool calls, nested tasks, and background jobs. The child then runs again on the same history with your message. The task keeps running, and the agent that started it gets the result of the new turn. Task chats offer guide and replace only, with no Up next group. See [Task chats](https://caudra.ai/docs/queue/#task-chats).

### Fixes

- **A stray indent no longer makes a server call unconditional**: Since Preview 12, a `code` snippet with a line indented deeper than its block, such as ` datetime.datetime.now()` after `import datetime`, has that line lined up with its block and runs. When the deeper block names a server or a host function, its indent may be all that is left of a missing `if` or loop, and lining it up would run its calls every time. Such a snippet is now rejected with `Unexpected indentation`, as before Preview 12. See [Results and errors](https://caudra.ai/docs/mcp/#results-and-errors).
- **Background work survives a brief database lock**: A brief database lock no longer stops goal or autopilot sessions from continuing after background tasks finish, and no longer cancels running subagents' shells; Caudra retries and says so in the chat if saving keeps failing.
- **No stale quota rows on accounts**: An OpenAI account could show a `secondary 100% left` row beside its `5h` and `wk` rows. That row came from a placeholder OpenAI sends for a limit the plan does not have, and it never went away. Caudra now ignores those placeholders, and a quota reading replaces what the same source reported before, so a window the provider stops reporting disappears. Rows saved by earlier versions clear on the account's next reading.
- **JSON keys have their own colour**: In a highlighted JSON file, such as a `read_file` card, a diff or the workbench editor, keys were drawn in the same colour as string values, so most of the file was one colour. Keys now take the theme's member colour, as YAML and TOML keys do, and string values keep the string colour.
