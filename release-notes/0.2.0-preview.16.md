- GPT-6.1 Terra is available in the OpenAI and Copilot model lists.
- The keybindings list filters as you type after `/`, and shows modifiers as compact symbols.
- `F2` opens an empty `/btw`, so a side question no longer needs the command typed first.
- On a terminal at least 30 rows tall, errors and notices get their own footer row, so they no longer push the context and spend meters off a narrow screen.
- Saved tool outputs move into the session database, compressed, and `caudra -p` runs are saved as sessions you can resume.

### Models

- **GPT-6.1 Terra.** Adds `gpt-6.1-terra` for OpenAI and GitHub Copilot, with vision and configurable reasoning. Existing default models remain unchanged.

### Changes

- **Narrower usage totals.** When `/usage` shows both billed and subscription spend, the subscription amount sits below the billed amount, aligned at the decimal point, with its legend on the same row. This applies to session and lifetime totals. A single amount stays on the headline.
- **Filter the keybindings list.** In the `F1` list, press `/` and type to keep only the keys whose action, key, or section matches every word. `Enter` keeps the filter and `Esc` clears it. The list is wider, every section starts at the same column, and modifiers show as `⌃`, `⇧`, `⌥`, and `⌘`. Typing `ctrl` or `shift` still finds them. See [Keybindings](https://caudra.ai/docs/keybindings/).
- **`F2` asks a side question.** Outside a modal, `F2` opens an empty `/btw` that reads the conversation, or the focused task's, when you send. A question you close without sending comes back on the next `F2`. See [Commands](https://caudra.ai/docs/commands/).
- **A footer row for messages.** On a terminal at least 30 rows tall, the footer has a third row for errors, retries, notices, `waiting for background work`, and the chips that wait on you, such as `[? 2]` or `[caudra.toml invalid]`. The row stays empty when there is nothing to say, so the composer never moves. A message too long for the row is cut in the middle, and resting the mouse on it shows the whole text. Chips with no room fold into a `[+N]` chip that lists them and opens the first on a click. With two rows or one, messages get only the space left once the meters reach their short form. The account chip now sits beside the spend, and it shortens to its quota before the price gives way. See [Quick start](https://caudra.ai/docs/quick-start/).
- **Saved tool outputs live in `caudra.db`.** The full output behind a truncated tool result is stored compressed in the session database rather than as a file under `tool-output/`, which takes about a third of the space. Trimming or deleting a session removes its outputs in the same transaction, and a fork copies them as part of its first save, so a fork that cannot copy one is not saved. Each output is now capped at 32 MiB, down from 100 MiB. The upgrade imports the existing files, skips those it cannot use, such as outputs of deleted or trimmed sessions, and then removes the directory. `/storage` no longer shows a tool output share, and `caudra storage stats` counts saved outputs instead. See [Sessions](https://caudra.ai/docs/sessions/#managed-tool-outputs).
- **`caudra -p` runs are saved.** A one-shot print run now saves its session when it ends, so it appears in session lists, its saved tool outputs stay readable, and `caudra --session <ID>` resumes it. See [Headless](https://caudra.ai/docs/headless/).

### Fixes

- **Stable colors while patches stream.** Patch previews keep their addition and removal colors without syntax highlighting until the tool finishes, avoiding repeated recoloring as text arrives.
- **`Scratch` is where temporary files go.** The workbench's `Scratch` folder now lists the temporary directory the agent is told to use, even after `/cd`, in a worktree, or in a session from another project. It used to list that project's own folder, which was often missing. See [Workbench](https://caudra.ai/docs/workbench/#files-outside-the-project).
- **Pictures in batches fold and open.** A `view_image` call inside a batch shows its picture, which opening the row used to leave blank. A `view_image` call is now a row in every view, with its picture open under it outside the compact view, and a click on the row folds or opens it like a `file_read`. See [Images](https://caudra.ai/docs/markdown/#images).
- **`code` runs in batches answer clicks.** A click on a call row or a printed tree of a `code` run inside a batch now opens and folds it, as it does on the run's own card. It used to highlight the row and change nothing.
- **Tool cards name empty results.** A search that finds nothing reads `no matches` or `no files` rather than `0 matches in 0 files`, an empty file or folder reads `empty`, and a single result is singular, as in `1 match in 1 file` or `1 entry`.
- **Opening a large session no longer looks frozen.** Choosing a session from the picker used to leave the closed picker on screen for seconds. It now shows a loading card over the current session, with a spinner, the session's title, the step it is on, and the seconds so far. The card stays up until the transcript is drawn, and recentres if the terminal is resized. Forking a session shows the same card. So does resuming one on startup, after a spinner line while the session is read before the full-screen view starts. A session that opens quickly shows no card.
- **Resume waits for a busy database.** Opening a session retries temporary database contention for up to 30 seconds, with a visible waiting status, instead of failing after the old five-second timeout. If the database stays busy, the error names the step that could not finish.
- **Importing a `code` module no longer stops the agent.** A snippet that imports a module already in scope, as `import history` or `from mcp import decisions`, now runs without the import, and the card lists the repair. An import that still fails, as `from mcp import search`, says to call the module directly rather than to give up on it.
