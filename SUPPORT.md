# Getting help

Pick the place that fits your request, so it reaches the right people and others can find the answer later.

| You want to | Go to |
| --- | --- |
| Look something up | The manual at [caudra.ai/docs](https://caudra.ai/docs/), or `/docs` inside Caudra for the pages that match your version |
| Ask a question about setup, configuration, or usage | [Discussions Q&A](https://github.com/caudra/caudra/discussions/categories/q-a) |
| Talk through an early idea | [Discussions Ideas](https://github.com/caudra/caudra/discussions/categories/ideas) |
| Report a bug, a provider or model problem, or a docs error | [A new issue](https://github.com/caudra/caudra/issues/new/choose), with the form that fits |
| Report a security vulnerability | Privately, as [SECURITY.md](SECURITY.md) describes. Never in a public issue |
| Report a code of conduct violation | Email [conduct@caudra.ai](mailto:conduct@caudra.ai), as the [Code of Conduct](CODE_OF_CONDUCT.md) describes |

A bug report with logs is much easier to act on. `caudra logs -n 100 -l warn` prints the latest warnings and errors. Logs leave out prompt text, model output, and tool input. Provider error messages are kept in full, so read the log and remove anything secret before you paste it.

To contribute code or docs, start with [CONTRIBUTING.md](CONTRIBUTING.md).
